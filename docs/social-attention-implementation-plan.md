# 社交注意与应答实施设计（S3-SOCIAL-ATTENTION-DESIGN-001）

状态：实施设计（2026-10-07，基线 `6b69f7e`）。上位契约是
[注意力与意图](attention-intent.md)；本文不重述契约，只回答"按什么顺序、以什么形状把它
落到本仓库"，并给每个切片标注**消费方**与**判据**。契约的设计结论（注意到一个事件、
将事件联系到某人、推断对方意图、选择回应是不同步骤；注意力有限、可失误且失误基于可观测
的任务负荷而非强制漏听；危险反射不等待注意力模型或 LLM；不补造漏掉的聊天；回敬不等于
认定仇敌）在没有逐条讨论时**原样成立**。

## 1. 现状（代码核验，2026-10-07）

已交付（同日多卡，条目见 `development-execution-plan.md` 追加二十六～三十一与运行手册
六之五十九～六十四）：

- **听见**：玩家聊天进观察面（`PlayerChatMessage`，drain 语义、溢出以 `chat_omitted`
  显式申报），每行落 `PlayerChatObserved`（`TrustClass.PLAYER_CHAT`）；
- **身份**：行携带稳定账号键 `sender_id`（改名不串人；同名两人两段历史）；服务端回响的
  自己的行标 `own`（自己的声音不冒充陌生人）；
- **回忆**：`recall_actor_history`（按键精确匹配、绝不按名并号），带键的说话者按决策挂进
  `DecisionRequest.actor_context`；
- **表达**：`say` 技能（模型选词；能力门、红线（空/超限/命令形）与每 run 预算；确认只有
  `CLIENT_SENT`，`KinSaid` 只对被接收的发送落账）；
- **纪律**：提示词写死 chat=证词非事实非许可、actor_context=这些人以前说过的话、
  own=没有人要应答。

没有：注意力作为**独立于模型的过滤**（今天每次 drain 都送进下一次 offer）；声音（非聊天）
注意；**受击的出手者归属**（观察里有血量变化，没有"是谁打的"）；对话积压/延迟的显式语义；
关系与信念（记忆计划切片 C）。

## 2. 设计决定（先于任何编码）

1. **v1 不做注意力过滤，且把"为什么"写死。** 契约要求失误"基于可观测的任务负荷而非强制
   每隔几次漏听"，而负荷数据只在真实社交场景里存在——在拿到那些读数前，任何过滤参数都是
   预填。今天"全部送达"是**诚实上限**：模型看得到一切，注意与否是它的判断；被打断时决策
   变差的风险由既有护栏承担（危险反射不等待模型；`say` 有红线与预算）。
2. **注意力切片的第一格是"省略要显式"，不是"漏听"。** 当 offer 的上下文预算将来被逼着做
   （会话变长、门槛到达）时，被省略的聊天/actor_context 行必须像 `chat_omitted` 一样**报数**；
   "没送达"与"送达了但没进这一格"必须是两个词。该切片与 offer 预算卡合并做（预算数值同样
   等真实读数，不预填）。
3. **受击归属是一格独立的观察能力（桥/线），是社交线的下一张桥卡。** 契约的"玩家轻打提醒"
   "谁在打我""回敬不等于认定仇敌"三个案例都要求出手者可观察。落地形状（画卡前先核基线）：
   观察增"最近受击来源"字段——**玩家等价**：只报客户端在受击帧渲染到的那一个实体，不查
   服务端真值、不建伤害表；落账一行（hurt 来源＋tick＋当时解释空位）；消费方=心的每次决策
   与未来的关系物化。判据：被打后一个决策内，包里有"可能的攻击者"及其观察出处；且**不**凭
   历史敌意或一句"开玩笑"认定故意（契约明文）。
4. **回应的一切判断归模型。** 没有自动应答规则；`say` 的能力门、红线与预算只是执行器的
   边界，不是对话策略。契约的"合作、拒绝、提条件、误判后修订"都长在模型选词上；Core 负责
   词能被安全、可核、有出处地送出去。
5. **关系/信念（切片 C）排在受击归属与地点面之后。** 先有观察（谁、哪里），才谈物化；物化
   的写者治理沿用切片 B 的候选机制（`commitment` 的家族形状：模型建议经网关校验、按证据
   落账、不作为动作许可）。

### 切片 B（下一张桥卡，等活体窗口）：受击来源观察

- 形状与判据见 §2.3。**桥侧现状已按设计自己的规则先核过**（2026-10-07，钉住的

  1.19.4 起的伤害倾斜渲染用）——出手者在受击帧**是可读的**，画卡时只需再定"客户端在

- 消费方（真实存在）：心在后续决策里的伤害归因输入；记忆切片 C 的"受击/损失"触发画像

### 切片 C（与 offer 预算卡合并）：注意的显式省略

  可数、可复现、与"没送达"（bridge 侧 drain 溢出）在文档里是两个字段。
- 等的是真实读数（会话长度与 offer 体积的实测），不预填阈值。

### 切片 D（等切片 B＋地点面）：关系与信念物化

## 4. 明确不做与仍未知

- **不做**强制漏听（无负荷数据前）；**不做**声音（非聊天）注意——它要一个新的观察面
  （客户端听得见的声音事件），等有真实场景再立卡，现在立只会写一个没人消费的字段；
  **不做**自动应答、自动回敬、自动问候。
- **未知**：真实玩家打断下"说错话"的代价分布（等活体）；注意力窗口的合适阈值（等切片 C
  的真实读数）；出手者渲染不到的场合（隐身、远射）取回包应说什么——切片 B 画卡时按判据表
  先写"取不到时说什么"，不留空白。

  同规；
- 本文件**不改变任何 `current_next`**；切片 B 画卡前先核桥侧受击事件的现状，核到什么写
