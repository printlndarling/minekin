# 开发路线与验收

以下阶段按能力依赖排序，不把时间估算当成承诺。先固定一个 Minecraft Java / Fabric 版本和私人测试服务器版本，调查依赖的兼容性、许可与服务器规则，再锁定构建配置。

正式编码前先完成[设计决策与待验证问题](decisions.md)中的关键检查。未解决的问题应标注假设和替代路径，不能因为文档看起来完整就当作能力已存在；原型阶段用小实验验证客户端输入、感知边界和紧急动作窗口。

| 阶段 | 可交付物 | 通过条件 |
| --- | --- | --- |
| 0：客户端闭环 | Fabric 原型、玩家等价观察、例外能力记录、合法输入、在线生命周期、回放日志 | 真实客户端账号进入测试世界；两种模式的加入/退出可核验；未授权隐藏真值不进入决策或底层目标选择 |
| 1：生存底座 | 本地反射、紧急抢占、导航/背包技能适配 | 模型关闭时仍能处理至少跌落预警、低血量和受击；中断后能检查并恢复任务 |
| 2：自治目标 | 需求、短/中/长期目标、人格式游玩偏好、游戏日回顾、原版世界书、受限后台资料查询、试做复盘及技能复用 | 没有真人输入时不同人格会推进不同的可观察目标；跨日可解释地调整计划；对当前版本的基础玩法有认知；失败能沉淀为下一次可用经验，不把查到资料当成已掌握技能 |
| 3：社会 MVP | 关系、权属、事件记忆、情绪、调查、拒绝与承诺 | 不同资源/关系状态产生合理不同的回应；未知犯人的损失触发情绪与可选调查，而非凭空指认；隔日仍能依据经历调整共享边界 |
| 4：完整演示 | 可回放的合作、冲突、归还与信任修复流程 | AI 行为受可追溯的亲历事件影响，且不靠隐藏信息得出结论 |
| 5：多 Kin（远期） | 每个角色独立客户端/心智、玩家间沟通、分工与共享约定 | 多个 Kin 可像玩家一样在同一世界合作、意见不合、竞争或结盟，不共享未观察的世界真值 |
| Future：模组玩法 | 模组内容知识、冲突版本与服务器公开规则的适配 | 单角色原版能力稳定后再单独设计，不进入首版验收 |

## 首批验收场景

1. **无人在线**：AI 依据资源与目标主动开始采集/建造；失败后重新规划而非无限循环。
2. **资源请求**：只有 5 个铁且正在做护甲时拒绝赠送 20 个；资源富余且关系良好时可以答应或谈条件。
3. **误伤与追击**：一次受击先避险和保留不确定性；连续追击提高威胁判断。两种情形在记忆和后续回应中有区别。
4. **权属与证据**：看到私人箱资源发生变化时保留不确定性；只有观察到取走、明确承认或其他可靠证据时才合理归因。
5. **道歉与修复**：一句“sorry”不能归零既往冲突；归还并多次守约后关系缓慢改变。
6. **悬崖跌落**：有/无水桶、可见/不可见落点、不同 TPS 与网络时延下多次回放，记录可操作窗口和成功/失败原因。
7. **感知越界**：普通模式中墙后玩家、未暴露地下矿物、未打开私人箱子不得进入决策或寻路目标；可选矿透模式须主动开启，矿点必须标明来源，不能提升其他隐藏信息权限。
8. **未知犯人的损失**：分别回放误放、自己移动、他人拿取、线索不足与虚假线索；角色可以沮丧、盘点、询问、悬赏或放弃，不能无证据准确指认。
9. **追责与修正**：在可信证据指向某人后，比较索回、和解、避让和允许环境下的报复；新证据推翻指认时能承认错误并修正关系。
10. **记忆污染与技能学习**：插入强烈但错误的传闻、相互矛盾的后续事实以及重复失败的技能尝试；检索能区分来源，决策会修订旧信念并避免机械重复失败。
11. **协作建刷怪塔**：玩家提出并达成合作，AI 承认不懂并在后台查询对应 Java/服务器条件；资料返回后说明来源和不确定性，核对材料与地形、商量分工，再尝试建造或提出其他方案。查询超时、网页错误、版本不符及中途受击都不得让角色卡死或虚报完成。
12. **陪玩上线**：无指定真人时 Kin 不在世界；被邀请后正常加入，真人下线时暂停手中建造、记录承诺、退出；下次被邀请时核对世界变化再继续。
13. **独立上线与切换**：无人在线时 Kin 自己推进目标；切到陪玩模式且指定真人离线后退出；切回独立模式后恢复计划。断线或服务器重启不重复执行旧动作。
14. **性格与心境**：同一资源冲突在善良、自利、记仇等角色中有不同选择；同一 Kin 今天不计较、明天心情好想开玩笑时仍能看出连续的人格和真实原因。
15. **恶作剧与误判**：在不同亲疏、损失和服务器规则下观察玩笑的选择；若玩笑伤害关系，Kin 能根据对方反应修正、道歉或坚持自己的态度，而非强行归零。
16. **单个 Kin 的多日目标**：速通、打怪、探险取向在同一出生条件下选择不同里程碑；跨日因发现、死亡、承诺或资源损失调整，不忘记仍有价值的长期方向。
17. **多 Kin 远期场景**：两名 Kin 分工修建共同基地，一名原先想速通，另一名想探险；共同计划由可见交流和约定形成，任何一方可拒绝或改主意，隐蔽观察不得同步给另一方。
18. **当前版本的世界书**：选定版本中新内容能按名称/ID找到适用知识；旧版本攻略、未收录内容和工具断网时能明确表示未知并采取保守行动，不捏造用法。
19. **自主学习与复用**：给 Kin 一份版本匹配教程和一次失败的刷怪塔施工，检查是否记录实际结果、保留竞争解释并在第二次选择适用的排错步骤；再注入偶然成功、旧版本攻略与新反证，检查候选方法是否降级/修订而非宣称已精通。
20. **自定义与随机人格**：用自定义描述和留空随机入口分别创建 Kin，检查核心偏好保留、随机配置连贯、重启后不重抽。
21. **少量例外**：比较玩家等价观察与自身运动/限域碰撞读取下的跌落和避障表现；再回放墙后玩家和埋矿，确认底层寻路不会用隐藏真值选目标。
22. **A 炫耀钻石与矿透（可选能力场景）**：比较 A 自述真实/吹牛、服主允许/不允许的组合；Kin 区分展示与陈述，按人格调查或选择，能力未配置时不假装已开，配置启用时矿点有来源并在关闭后成为可能过期的记忆。

## 衡量方式

| 指标 | 解释 |
| --- | --- |
| `event_to_input_ticks` | 紧急事件到首次合法输入的 tick 数，报告分布而非只报均值 |
| `reflex_success_rate` | 分物品与环境配置报告的救援率，允许失败 |
| `stale_intent_rejected` | 危险期间过期 LLM 意图被丢弃的次数 |
| `unauthorized_read_count` | 未声明的隐藏世界读取和底层目标搜索次数，目标为零 |
| `belief_leak_count` | 未授权或仅供短时动作例外的信息进入世界信念/社会判断的次数，目标为零 |
| `exception_usage_trace` | 已声明例外的用途、读取范围、消费者、效果及是否错误持久化 |
| `claim_evidence_trace` | 玩家说法、亲眼观察、公开规则及反证的关系；怀疑/信任的变化能否追溯 |
| `perception_mode_trace` | 矿透等可选模式的配置、主动启用/关闭、发现出处和关闭后的缓存处理 |
| `goal_progress` | 无人指令时能否持续推进自定目标、失败后能否改计划 |
| `social_consistency` | 同一经历在跨会话决策中的影响是否可追溯、是否接受新证据修正 |
| `emotion_action_trace` | 情绪变化是否有事件出处、是否实际影响目标和互动，而非只改变措辞 |
| `attribution_accuracy` | 调查中正确指认、保留未知与错误指认的数量及证据来源 |
| `memory_revision_trace` | 旧信念如何被新证据修订，及关键决策能否追溯到原始经历 |
| `research_to_action_trace` | 从承认未知、发起查询、核验来源到实际试做及失败修订的完整链路 |
| `mode_lifecycle_trace` | 模式、真人在线事件、客户端连接状态、任务暂停与恢复的时间线 |
| `personality_continuity` | 初始价值观、跨日心境、事件与行动之间是否有连贯且可追溯的关系 |
| `persona_creation_trace` | 自定义设定保留程度、随机种子与人格配置的可复现性 |
| `goal_horizon_trace` | 短期行动到中期里程碑和长期方向的关联、调整原因及真实进展 |
| `world_guide_accuracy` | 按当前版本抽样的基础知识、新增内容、过时资料和未知内容的正确率与来源 |
| `learning_reuse_trace` | 从问题发现、资料/事件出处、试做结果、方法修订到再次复用的完整链路与条件检查 |
| `repeat_failure_rate` | 相似条件下是否反复执行同类失败方法，报告降级、修订或停止原因 |
| `model_cost_and_latency` | 每小时调用量、令牌量、延迟分布以及断连时的生存表现 |

第一版不以“通关游戏”“永不失误”或真实人类表现为验收标准。演示必须区分脚本化事件输入和 Agent 自己产生的选择，并附观察/意图/动作的时间线，以便检查行为是否真的源于角色内部状态。
