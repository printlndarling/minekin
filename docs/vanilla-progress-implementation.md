# 原版进度链：远期通关，不是固定剧本

首个研究基线暂用 Java 1.21.4；通关是默认**可放弃的远期方向**，不是强制日程，也不是首个身体技能原型必须打败龙。Kin 可选择生活、建筑、冒险、朋友协作，且可恢复、搁置或放弃龙目标。重要选择由 PlayerMind 结合个人兴趣、风险、关系和已观察的资源作出，基础控制器只负责执行已授权的小任务。

## 有前提的里程碑图

下面列出游戏机制依赖，而非“出生→必挖钻石→必进下界”的行动脚本。[Minecraft 官方 Stronghold 说明（2024-07-04）](https://www.minecraft.net/en-us/article/stronghold)明确末影珍珠与烈焰粉合成末影之眼，利用其投掷方向寻找要塞、给末地传送门填眼；投掷可能消耗眼。[Minecraft 官方通关指南（2022-05-18）](https://www.minecraft.net/en-us/article/how-beat-minecraft-under-30-mins)介绍下界、堡垒、烈焰棒、末影珍珠与进入末地的路径，但它是**速通示例**，不是 Kin 的规范流程。具体行为以候选版本与实际正常客户端反馈核验。

| 可选阶段 | 前提/条件检查 | 正常玩家式动作与可观察完成信号 | 失败、替代与主动暂停 |
| --- | --- | --- | --- |
| 生存与基本物资 | 当前装备/食物/工具不足，附近可感知资源 | 找树、取木、合成、补食物、避险；核对背包和游戏日 | 可以等炉、种地或探索，不把输出率作为人格目标 |
| 下界准备与入界 | Kin 愿承担危险，所需传送门材料/生存准备可获取 | 建门、正常使用、确认新维度、记返程位置；不能凭未观察地图选堡垒 | 没有材料/装备时延期；必要时撤退或换途径 |
| 烈焰资源与末影珍珠 | 有安全且可见的探索路径，角色理解风险 | 发现目标后靠近/战斗/拾取；通过自己的背包核对所得；取得足量眼作为动态目标 | 不强制堡垒→猪灵交换速通路线；危险高、路径失败、本人不愿时改计划 |
| 要塞与末地 | 有眼、可承受探索和战斗损失 | 正常投掷眼、记**亲眼观察的方向**、探索地下要塞、查看实际门框、填眼入界 | 投掷可能损失眼；方向只是观察证据，不读取世界种子/定位命令 |
| 龙战与返回 | 有生存准备、可执行的视角/战斗/撤退技能，目标仍被 Kin 认同 | 观察龙与战场，正常攻击/保命；确认击败和可用的回归路径，返回主世界 | 首版 PvE 动作能力不等于龙战成功；可失败重试或放弃，死后仍是同一个 Kin |
| 之后的人生 | Dragon 目标完成或放弃 | Kin 自行选生活、建造、探险、社交、挑战；长期人格/关系记忆延续 | 不自动重新刷一条通关流水线 |

这里的“眼数量”“装备准备”“值得取回遗物吗”不是固定阈值：公共规则、当前库存、可能的损失、兴趣和熟练程度共同决定具体计划。可用工具与物品配方须以候选版本世界书及实际 GUI/背包确认，不因网页写了“已完成”而标记完成。服务器的公开规则/数据包若改变机制，版本资料先降为待证；不使用私有配置或管理员视角。

## 任务表示、失败恢复与验收

每个里程碑使用 `goal_id`、本人理由、阶段/候选下一步、所依赖的公开知识与观察、当前先决条件、撤退条件、允许的身体动作、当前状态（进行中/暂停/放弃/完成）及自我复盘；每一步必须有**实际客户端可观察的结果**，跨维度/重生/断线不得静默推定成功。低层动作失败返回“路径不可见”“GUI 未确认”“库存未变”“危险抢占”等具体事实，由 Kin 决定重新规划、求助或放弃。

开发阶段的必要原型：先按[动作契约](action-contracts.md)单独验证取木、采集、配方、入门与跨维度，再测投眼方向记录、要塞门框、末地战斗/返回。私人测试服回放“出生缺装备却收到立刻下界邀请”“眼消耗/目标路径错”“战败且想放弃”“回归后改做农场”，检查自主拒绝、渐进计划与事件证据。**本文是可实施研究方案，尚无 Kin 实跑通关证据。**
