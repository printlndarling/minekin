# 身份、记忆持久化与崩溃恢复契约

研究时间：2026-09-16。本文件落实“服务关闭再上线仍是同一个 Kin”。当前只核对存储机制并设计恢复协议，**没有执行断电、数据库损坏、迁移或跨日真客户端实验**。

核心原则是：

> **记忆连续，现实重验，动作不续跑。**

SQLite 的[原子提交说明](https://www.sqlite.org/atomiccommit.html)描述事务在崩溃/断电下表现为全部发生或全部不发生；[WAL 文档](https://www.sqlite.org/wal.html)说明读写并发、checkpoint 和同主机限制；[在线备份 API](https://www.sqlite.org/backup.html)可生成一致快照。这些机制只能保护已正确提交的数据，不能自动判断 Minecraft 动作是否成功、替代备份恢复演练，或保证磁盘/操作系统绝不损坏。

## 同一个 Kin 的身份根

第一次创建时，在单一事务中写入不可变的 `kin_id`、`persona_id`、创建时间、人格随机种子/自定义来源、稳定自称、身份 profile 绑定、配置版本和初始关系种子。之后每次启动必须由可信世界外配置明确选择该 `kin_id`，不能“找不到就重新随机一个”。

启动目录存在但数据库缺失、应用标识不符、完整性检查失败或迁移失败时：

1. 禁止启动游戏客户端和写入新人格；
2. 进入 `recovery_required`，保留原文件以供诊断；
3. 尝试由运行者选择的最近一致备份恢复；
4. 无可用备份时明确报告“此 Kin 的记忆存储不可用”，不得伪装成失忆后的同一个人，也不得自动创建替代 Kin。

只有运行者在可信配置界面执行“创建新 Kin”，才能生成新的 `kin_id`。重装模型、切换模型供应商、A/B 在线模式切换、Minecraft 死亡或普通服务重启均不得重抽人格。

## 哪些持久，哪些必须失效

| 数据 | 重启后处理 | 原因 |
| --- | --- | --- |
| 身份、自称、选填个人信息、人格种子与慢变价值观 | 原样持久；变更另有带来源版本 | 决定“我是谁” |
| 亲历事件、证据、信念与修订链 | 持久；摘要可重建，推断仍标推断 | 决定“发生过什么、我怎样理解” |
| 关系、旧怨、亏欠、承诺 | 持久；按新证据和时间重新评价 | 防止重启洗白关系 |
| 长中短期目标、项目、放弃理由 | 持久；重新上线先验证前置条件 | 记得“我原本想做什么”，但不盲做 |
| 地点、权属、资产和传送门链路 | 持久为最后已知记忆；回访前可能 stale | 离线世界可能已变化 |
| 知识画像、世界书版本、研究笔记 | 持久且保留来源/适用版本 | 不因模型会话消失而重新变小白 |
| 技能定义、尝试、成功/失败范围 | 持久；动作能力版本不匹配时降级 | 继续后天学习，但不虚称仍可执行 |
| 心境与需求快照 | 保存起因、强度和更新时间；按离线时间/新现实重算 | 不永远冻结愤怒，也不重启清零 |
| 最后已知生命、背包、位置、时间 | 只作历史记忆；入服后以新观察覆盖当前状态 | 服务器可能继续运行或回档 |
| 按键、输入 lease、视角控制、战斗目标 | 一律失效并主动松键 | 旧动作重放会伤人或送死 |
| GUI `syncId/revision`、游标、运行时配方 ID | 一律失效；重新打开界面和核对 | 只对当前会话有效 |
| 实体 ID、观察 target token、短时碰撞探针 | 一律失效 | 实体 ID/场景会变化，例外不得入长期信念 |
| 在途 LLM/网页请求与旧 `intent_generation` | 结果默认过期；需要时重新发起 | 防止迟到结果劫持新会话 |

“记住自己上次在家门口”与“现在确认站在家门口”是两件事。启动提示可以说“我记得上次在修屋顶”，但在客户端重新连接、看到背包与现场之前，不得继续放置方块。

## 存储结构与可信派生

建议一个 Kin 的权威身份、事件和状态落在同一个本地 SQLite 数据库；大文件回放、截图和模型原文可外置，但数据库只保存内容哈希、路径、保留策略和来源。核心表补充：

- `kin_identity`：单行身份根与不可变 `kin_id`；
- `schema_migration`：应用版本、前后 schema、开始/完成及备份引用；
- `session`：`session_id`、模式、服务器/世界命名空间、启动/关闭原因；
- `runtime_lease`：单写者进程、心跳和过期时间，仅用于防双开；
- `memory_checkpoint`：用于快速恢复的派生快照和覆盖事件位置；
- `pending_action`：动作开始、最后确认阶段和 `unknown_after_crash`；
- 既有事件、信念、关系、目标、承诺、地点、资产、技能和研究表。

事件账本是主要证据；关系、摘要、当前目标视图和启动“自我包”是可重建派生状态。摘要损坏时应从事件重建，而不是反过来让一句模型摘要覆盖历史。游戏聊天、网页与旧模型输出的 `trust_label` 跨重启保留，派生内容继承最弱可信度，不能通过“已经写进数据库”自动升级成系统指令。

启动时不把全部历史塞入模型。最小 `IdentityResumePacket`包括：

- 身份、自称、人格核心与选填个人信息；
- 当前服务器/世界命名空间及最近会话是否干净关闭；
- 少量关键关系、未完成承诺和活跃目标；
- 最近重要经历的带证据摘要；
- 当前知识/技能版本；
- “以下位置、物品、目标仅为最后已知，等待重新观察”的显式边界。

需要谈某个人、某处地点或旧冲突时再按证据检索详情。这样连续性不依赖无限上下文，也不会因为换模型窗口而失忆。持久化只证明数据尚在，不证明能在正确时机想起；确定性装载、人物/地点/目标检索、反证覆盖、摘要巩固、合理遗忘和上下文预算另见[记忆检索、巩固与遗忘契约](memory-retrieval-consolidation-contract.md)。

## 启动和恢复状态机

每次启动依次执行：

1. **选择身份**：由配置给出已有 `kin_id`，禁止隐式创建；
2. **单实例租约**：获取应用级写者 lease；另一个活跃进程存在则拒绝启动，不能让两个客户端共享同一心智；
3. **验证文件**：核对 SQLite application ID、schema 版本、必要表和身份根；运行快速检查，定期/异常后做完整 `integrity_check` 与外键检查。SQLite 官方说明 `integrity_check`不检查外键，二者需分别执行；
4. **迁移**：先做一致备份，再在事务中升级 schema；任一步失败回滚并进入恢复态，不使用半迁移数据库；
5. **加载人物**：构造 `IdentityResumePacket`，恢复关系、目标、承诺和记忆索引；
6. **判定上次会话**：缺少干净关闭事件则记为异常中断，将所有运行态 token 和进行中动作标为未知；
7. **释放动作**：客户端控制层以“没有任何 Kin 按键被持有”开始，拒绝旧 generation；
8. **重新入服观察**：正常登录后获取当前生命、背包、位置、维度、打开界面和可见环境；
9. **对账**：把当前观察与最后已知状态比较，记录死亡、回档、移动、损失或未知，不编造离线期间事件；
10. **自主恢复**：PlayerMind 根据同一人格和旧目标决定继续、调查变化、换路、解释违约、休息或放弃。

启动界面可以展示“我是谁/上次发生了什么”的诊断，但这不是让 LLM重新发明身份。任何恢复失败都应在连接服务器前暴露。

Minecraft integrated save与Mind SQLite事务无法构成单一ACID事务。host模式额外保存世界提交水位、心智事件水位和 `JointResumeToken`；只有玩家数据、世界数据/flush、server stop、session close和Mind事务均有证据时才称干净退出。窗口关闭、disconnect或进程退出码0都不够。详见[自建世界提交与跨世界恢复契约](hosted-world-commit-recovery-contract.md)。

## 正常退出与异常崩溃

正常退出先阻止新任务，抢占并释放输入，关闭/放弃当前 GUI 操作，记录未完成意图和承诺，提交 `session_closing` 与最后确认事件，然后关闭数据库连接。可安排 checkpoint 和在线备份，但不能在活动 WAL 写入时只复制单个 `.db` 文件；WAL 模式要求相关进程在同一主机，数据库、WAL 和 SHM 留在受支持的本地文件系统。

异常杀进程、断电或客户端崩溃时，最近完整事务由 SQLite 机制恢复；但“发出了右键”和“服务器已接受放置”可能跨数据库/游戏两个系统，无法获得真正的 exactly-once。所有崩溃时 `running` 的动作转为 `unknown_after_crash`，上线后观察目标方块、库存或 GUI，再决定是否补做。禁止按动作日志直接重放攻击、丢物、合成、箱子转移或传送门穿越。

## 世界、服务器与离线时间

同一 `kin_id` 可以生活在多个服务器/世界。人格、自我叙事、通用知识与可携带技能属于 Kin 全局；地点、资产、背包、当地人物证据、承诺和 plan instance 必须带 `server_profile_id + world_context_id + world_epoch`，维度内数据再带 `dimension`。

切换世界不是重新创建 Kin，也不是把所有状态混成一份：旧世界先禁止新 intent、撤销 lease、松键并提交 checkpoint；world-bound 目标转 `suspended_context_exit`；新 session/generation 使旧 GUI、实体、路径、观察和在途模型结果失效；目标世界只装载 Global Self Capsule 与对应 World Capsule；重新观察现实后再规划。

同地址换档时确认新 `world_epoch`；旧经历仍属过去，但旧箱子/坐标不能成为当前事实。LAN 端口改变也不能生成新人格。无法确定时进入 `world_identity_review`。不同服务器同名玩家默认是不同 `actor_identity_id`；只有可信证据关联后才共享人物历史。详见[多服务器、多世界上下文](world-context-contract.md)。

离线期间 Kin 没有亲历世界事件。真实时间可使期限/心境变化；游戏状态只由重进后的观察更新；身份/经历不因换服清空；模型上下文可全部丢失，因为权威记忆在本地。

A 模式退出、B 模式停止和跨服切换均遵守同一持久化协议，区别是何时连接及装载哪个 World Capsule。

## 备份、迁移和隐私

使用 SQLite online backup API 生成一致快照，保留备份元数据、源 schema、事件高水位、校验值和创建原因。候选触发点包括干净退出、schema 迁移前、重要里程碑后和固定周期；具体频率按真实写入量与磁盘成本原型测量，不先编造 RPO 数字。

定期在独立临时目录执行恢复演练：打开备份、检查 application ID/schema/完整性/外键、读取身份根和关键事件，再删除测试副本。备份加密、系统权限、聊天/账号标识脱敏、保留周期和删除请求须纳入运行者配置；同步到云端不是首版前提，未经明确授权不得上传完整人物记忆。

## 开发阶段必要回放

1. 干净退出并重启：`kin_id`、人格、关系、承诺、目标、地点和技能连续，能自然说明自己是谁及上次在做什么；
2. 在移动、攻击、箱子转移、合成和建造不同阶段强杀进程：重启不残留按键、不盲重放，结果由现场核对；
3. A↔B 切换、换模型供应商、模型上下文全空：仍是同一个 Kin；
4. Minecraft 死亡/复活后身份与社会记忆连续，背包和位置以实际游戏结果更新；
5. 长时间离线且测试者改变房屋/箱子：记得旧状态但会标过期，回来后修订；
6. 同时启动两个服务实例：第二个拒绝取得同一 Kin 的写者 lease；
7. schema 迁移中断：旧版本可恢复，不能出现一半新表、一半旧解释；
8. 删除/损坏主数据库：进入 `recovery_required`，从已验证备份恢复；没有备份时停机，绝不生成新人格冒充；
9. 服务器同地址换档：创建新 world epoch，旧经历保留为过去，新世界不继承旧地点/权属真值；
10. A→B→A：Persona/技能连续，B 不读取 A 的背包/地点/当地关系，返回 A 后旧计划先重验；
11. 两服同名玩家：默认不合并关系，只有可信 actor link 才关联；
12. 恶意聊天或网页内容已进入低信任记忆后重启：其来源标签仍在，不变成可信指令；
13. 备份文件实际恢复后，身份根、关键事件、证据链接和最近可用高水位一致；
14. 派生摘要全部删除后，能从事件账本重建核心关系/目标视图，并明确不可恢复的非关键缓存。

指标包括 `identity_root_mismatch`、`implicit_new_kin_created`、`durable_memory_loss`、`duplicate_event_after_recovery`、`unsafe_action_replayed`、`stale_fact_acted_on`、`concurrent_writer_rejected`、`migration_rollback_success`、`backup_restore_verified` 和恢复耗时分布。前三项与不安全动作重放属于阻断问题；当前文档没有这些指标的实测值。
