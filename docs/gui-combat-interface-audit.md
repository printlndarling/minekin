# 1.21.4 GUI 与近战输入：接口实证和未证事项

复核：2026-09-16；候选 Yarn `1.21.4+build.8`。本页依据 **Fabric 官方发布的该版本 Yarn Javadoc**梳理首个 Kin 动作原型的实现约束；没有构建或客户端/服务端实跑。现有逐阶段动作设计见[动作契约](action-contracts.md)，这里只补会影响实现可靠性和公平性的具体签名。

| 动作 | 该版本直接证据 | 实现决定与尚未证明的事项 |
| --- | --- | --- |
| 木头破坏/放置 | [`ClientPlayerInteractionManager`](https://maven.fabricmc.net/docs/yarn-1.21.4%2Bbuild.8/net/minecraft/client/network/ClientPlayerInteractionManager.html)列 `attackBlock(pos,direction)`、`updateBlockBreakingProgress(pos,direction)`、`cancelBlockBreaking()`、`interactBlock(player,hand,hitResult)`；还列 `breakBlock(pos)` | 经当前准星、距离、所持工具、按正常破坏进度与服务器反馈控制；**不能仅凭名字说 `breakBlock` 是游戏外挂或安全的直接瞬挖**，也不调用创意模式增加物品；正常玩家输入路径需用客户端源码/真实服继续验证 |
| 配方/GUI | 同类提供 `clickRecipe(syncId,NetworkRecipeId,craftAll)`、`clickSlot(syncId,slotId,button,SlotActionType,player)`、`clickButton`；[`ScreenHandler`](https://maven.fabricmc.net/docs/yarn-1.21.4%2Bbuild.8/net/minecraft/screen/ScreenHandler.html)列 `syncId`、`getRevision()`、`getCursorStack()`，说明槽位通常由服务端控制并同步到客户端，游标暂存物品且关窗时可能进背包或掉落 | 从已**正常打开**的当前 handler 和实际槽位读状态，配方 ID 必须从当前可用/已知配方环境选取，不能把世界书的文本 recipe 当一个合法 `NetworkRecipeId`。每次 `clickSlot` 前重查 handler、syncId、当前游标/槽位、期望变更，发送后等同步或超时标记 `unknown`；**不能假设 revision 递增本身证明服务端已确认** |
| GUI 紧急抢占 | ScreenHandler 文档说明 closing 时游标栈可能进入背包或成为掉落物；不等同“关 GUI 必保住材料” | 本地遇致命危险可抢占，但若游标持宝贵物资应先快速结束可确认的拿放步骤；无法安全结束仍须先保命，记录关窗前后游标、库存/掉落与损失。行动恢复须重新开界面取得新 handler，不重复可能副作用的旧点击 |
| 玩家可见目标和剑/盾 | [`MinecraftClient`](https://maven.fabricmc.net/docs/yarn-1.21.4%2Bbuild.8/net/minecraft/client/MinecraftClient.html)有 `crosshairTarget`、`targetedEntity`；交互管理器 `attackEntity(player,target)`、`interactItem(player,hand)`、`stopUsingItem(player)`、`hasLimitedAttackSpeed()`；[`PlayerEntity`](https://maven.fabricmc.net/docs/yarn-1.21.4%2Bbuild.8/net/minecraft/entity/player/PlayerEntity.html)列 `getAttackCooldownProgress(float)`；[`LivingEntity`](https://maven.fabricmc.net/docs/yarn-1.21.4%2Bbuild.8/net/minecraft/entity/LivingEntity.html)列 `isUsingItem()`、`getActiveItem()`、`getActiveHand()` | 近战锁定只能按允许的当前视野目标与准星、遮挡、距离/角速度进行；攻击按当前攻速与本地人类化转向/失败反馈控制。盾牌从实际手持/副手的使用动作进入使用状态，停止后核查 `isUsingItem/activeHand/activeItem` 与服务端反馈。**这些公共方法本身无法阻止直接 `attackEntity` 给墙后任意 Entity**，授权限制由 Kin 执行层强制实现 |

最低行动状态机：`observe → validate current target/handler → acquire one input owner → issue one normal action → wait for client/server observation or timeout → confirm / unknown / interrupt`。GUI 步骤需要保护当前游标与窗口所有权；战斗步骤持续刷新目标观察/攻速/使用状态，失明时转头、撤退或断联而不是拿实体列表追踪。服务器可能禁 PvP、改配方或处理器，且客户端预测/返回值不代表服务器收下动作；测试应至少覆盖 GUI 移物时受击、慢同步/关窗/重连、配方不可用、盾牌被切换、目标穿墙与攻速/盾牌失效，记录真实失败。所有结果由后续原型回放确认，不能把接口实证替换成动作成功或 PvP 强度证明。
