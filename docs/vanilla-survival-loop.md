# 首登原版生存：从观察到合法动作

“先撸树”可作为首登时常见的短期方向，不是每个 Kin 必须执行的脚本。有的人先找树做工作台和工具；有的人先看周围是否有村庄、食物或安全地形。PlayerMind 提出 **获取基础材料/提高生存能力** 等目标，任务层把它拆成条件化动作，本地控制持续确认进度、危险、可及性和实际结果。

## 可复用的基础动作闭环

| 动作能力 | 首次生存示例 | 最关键的输入/结果检查 |
| --- | --- | --- |
| 观察与寻找 | 转头寻找视野中可见树木、地表石头、食物或合适地形 | 目标要源于合法观察/过往地点记忆，未知区域靠探索而非扫描隐藏方块 |
| 导航 | 走到已知树木，绕开坑、危险或他人领地 | 路径使用允许的地形信念，失去目标或过期地图时重新观察 |
| 破坏和拾取 | 对准木头使用正常挖掘动作、接近掉落物 | 工具/距离/破坏耗时真实有效；库存实际增加才算采到 |
| 背包与合成 | 将木头转成木板/木棍、做工作台、镐或斧 | 当前版本配方与打开的真实界面匹配，确认合成/放置成功 |
| 后续采集 | 用适合的工具取石头、铁、食物或羊毛 | 工具升级有前置条件，不把掩埋矿物坐标当发现 |
| 搭设生存点 | 放工作台/炉子，必要时做床、临时庇护或储物 | 物品真实放置、可再次找到；保护已有建筑与权属约定 |

任务依赖是**可中断的资源图**，例如“需石制工具 → 缺圆石 → 先有镐 → 缺木板/木棍 → 找已见树木”，已在背包里的材料直接跳过；路线有多个选择，不强制制作斧头才能砍第一棵树。饥饿、低血量、被攻击或朋友求助可以改优先级；中断后重新核对背包、地点和承诺，不从旧计划重复砍已不存在的树。当前困难需反馈目标层：树不可达时换树/探索，配方不符时查[版本知识](world-guide.md)，夜间危险时临时避险，材料不足时改计划。

## 轻量底座核查与局限

- [Baritone 1.21.4 固定版使用文档](https://github.com/cabaletta/baritone/blob/78d3613e8c2e4c2f4bb56a6d84fe2844bd6d22e8/USAGE.md)列出 `goto`、`mine`、`farm`、`build`，且对 `legitMine` 有“只采它能看到的矿”之类的使用说明；**这只是上游文档的功能描述，不能当作 Kin 的当前画面可见性证明**。[同 commit 的 `MineProcess`](https://github.com/cabaletta/baritone/blob/78d3613e8c2e4c2f4bb56a6d84fe2844bd6d22e8/src/main/java/baritone/process/MineProcess.java)在 `legitMine` 路径仍先查询附近方块状态再判断可达，而一般模式还有缓存/区块扫描。未运行完整采矿链，不把这种源码能力误称为实际作弊或集成兼容；普通模式优先只为已观察目标试受限导航，矿点发现需要自写过滤或通过原型证明每个读数与目标消费均在允许域，见[源码审计](baritone-perception-audit.md)。
- [AltoClef 的使用文档](https://github.com/gaucho-matrero/altoclef/blob/main/usage.md)给出 `get`、`food`、`deposit` 等资源任务；其[设计说明](https://github.com/gaucho-matrero/altoclef/wiki/1:-Documentation:-Big-Picture)展示材料依赖、已有物品跳过和防御/食物任务抢占。原仓库已归档，直接接入当前 Java 版本和客户端感知边界并未得到验证。
- 两者均不是“Kin 已经会原版生存”的证明。初期可借用资源图、局部寻路和动作分解思路，感知/客户端输入/任务反馈要以可审计的 Kin 适配接口实现。[感知政策](perception-policy.md)覆盖底层目标选择；其特殊矿透模式不能暗中成为普通开局找矿能力。

GUI 合成、挖掘时长、拾物、炉/箱以及战斗/施工的候选客户端接口和服务器同步契约，详见[玩家式动作契约](action-contracts.md)。这些是依据 Yarn Javadoc 提出的实验路线，还不是已运行验证的 Kin 动作。

## 已收敛候选与强制原型验证

现有静态调研已完成版本、接口、许可和感知风险的候选收敛；剩余内容不能靠继续查 README 证明，必须分阶段运行：

| 阶段 | 固定路线 | 必须验证的结果 | 失败处理 |
| --- | --- | --- | --- |
| VSL-00 | 复用 P0 core 的玩家等价 snapshot 与最小合法输入 | 已见树目标可表示；look/move/release 无隐藏扫描或残留输入 | 修正 observation/action contract，不进入导航 |
| VSL-10 | 独立 `p0-nav-exp`；先限制为已观察目标和允许地图 | 到达可见树，坑/失目标/地图过期会重观察；缓存 canary 不泄漏 | 隔离 Baritone并自写局部导航，不污染 core |
| VSL-20 | 正常 attack/use 破坏方块并接近掉落物 | 破坏时长、距离、工具和服务端结果真实；库存增加才算成功 | 调整时序/瞄准；禁止直接加物品 |
| VSL-30 | 当前会话真实 Inventory/ScreenHandler 与版本配方知识分离 | 木板/木棍/工作台/镐逐步成功；GUI revision、焦点和结果可核对 | 回滚 GUI 事务；不得伪造 recipe id或跳过合成 |
| VSL-40 | 资源依赖图组合 VSL-00…30 | 空手→木头→工作台→木镐→圆石链可中断、恢复且不重复旧事实 | 将失败反馈目标层，不能硬编码脚本补物品 |
| VSL-50 | 权属/保护规则作为寻路和破坏前置约束 | 不拆自有/他人物资；无合法路径时报告失败 | 收紧动作许可，不用效率覆盖产权 |
| VSL-60 | 在前述通过后扩展炉、箱、床、食物和夜间避险 | 每项有独立 GUI/世界结果、取消和故障恢复证据 | 单项隔离，不用“能合成”推定全生存 |
| VSL-70 | 模型断连、受击、死亡、重启回放 | 本地安全层持续工作；重启后同一 Kin且现实重验 | 阻断该能力晋级，不宣称无人值守生存 |

首轮不以“自动通关”验收。VSL-00…40 通过只证明基础生存动作闭环；生活目标仍由 Kin 决定，不能把“先撸树”固化成人格脚本。P0 core 的前置顺序见[P0 核心原型执行计划](p0-prototype-execution-plan.md)。
