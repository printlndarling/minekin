# 设计决策与待验证问题

本文件记录产品原则与工程假设的状态。`已定原则`代表项目想实现的行为边界；`待验证`代表目前不能从设计文档推断为可行；`待选择`代表存在真实取舍，需要后续讨论。提出新方案时更新此表及受影响的架构、PlayerMind 和路线图。

## 已定原则

| 原则 | 对实现的约束 |
| --- | --- |
| 自治玩家 | 没有人发出指令时也能产生并推进自己的目标；人类请求只是可拒绝的社交事件 |
| 真实客户端 | 用 Minecraft Java 客户端和独立账号正常加入测试世界，行动最终经过合法客户端输入 |
| 分层控制 | 紧急反射在本地执行，LLM 不参与逐 tick 操作；危险可抢占并使过期意图失效 |
| 玩家等价感知与例外 | 默认使用玩家可知信息；成本或操作困难时可声明少量限域、限时读取例外，但不能暗中变成隐藏世界知识 |
| 可选作弊行为与自主判断 | 矿透等改变感知的能力须独立配置并由 Kin 主动启用，记录来源与社会后果；玩家说法不能直接升级为事实或能力许可 |
| 长期社会状态 | 权属、承诺、关系和情节记忆影响跨日行动；道歉与传闻不直接改写事实 |
| 分层记忆 | 工作、亲历、归纳信念、技能经验和自我叙事有不同生命周期；重要事件保留证据与修订链 |
| 情绪影响行为 | 损失可先引起难过或警惕；情绪参与目标排序、调查和互动，不能当作已查明事实 |
| 外部工具可选 | 角色可主动查公开资料补足知识；工具结果不能越过游戏感知边界或直接控制客户端 |
| 在线模式可选 | 陪玩与独立玩家两种模式共用身份和自主性；运行模式决定上线/下线规则，不变成服从等级 |
| 人格有连续性 | 创建时可自定义人格或留空随机生成；初始配置持久保存，心境与经历再影响行为和倾向 |
| 游戏能力独立 | 创建时按领域能力多边形自定义或随机，可有极不均衡的长短板；具体高阶动作需训练与条件检查，不能用单一强弱档位代替 |
| 注意力、意图、损失分层 | 专注任务可漏听；受击先按风险保命，但不自动证明敌意；相信对方本意良好也不强制原谅误伤造成的死亡或财物损失 |
| 多层自主目标 | 单个 Kin 从游玩偏好产生短、中、长期目标，按游戏日与事件调整，不依赖玩家发布任务 |
| 原版世界书 | 首版预置 Java 原版生存的基础常识与当前游戏版本知识；不熟悉的细节才用外部工具查，模组内容放 future |
| 自主学习 | Kin 可从公开资料和游戏亲历形成候选方法，经过可观察结果及前提检查后复用；失败、反证或版本变化会修订/降级技能 |
| 可失败 | 操作与推断会出错；追求一致且可解释的玩家行为，而不是全知和永不失误 |

## 关键待验证假设

| 问题 | 为什么会影响核心体验 | 最小验证与不成立时的方向 |
| --- | --- | --- |
| Fabric 客户端能否稳定接管正常移动、视角和使用物品 | 决定是否真能以客户端而非协议机器人行动 | 单客户端在私人世界完成可回放的行走、转向、取物和交互；若不稳，调整客户端适配方案，不能悄悄改成服务端特权 |
| 导航/任务底座能否接受受限观察 | 某些寻路器可能直接查询加载区块，泄漏墙后和地下信息 | 在墙后目标和埋藏矿物场景审计实际查询；必要时限制可用地图或替换技能实现 |
| 少量读取例外能否提高体验而不扩散为全知 | 限域碰撞与自身运动数据能辅助救援，底座缓存却可能把隐藏真值带进目标选择 | 对每种例外定义字段、范围、消费者和能否入记忆；回放跌落、避障、墙后玩家和埋矿，分别测收益与泄漏 |
| 普通客户端能否取得足够的权属证据 | 箱子数量变化不能证明谁拿走，更不能证明拿取意图；仅靠戏剧化剧情容易隐含作弊 | 测试亲眼看见交互、自己打开箱子后盘点、玩家承认、公开约定等合法证据；若不足，首个冲突演示改为角色确实观察到的物品转移或毁坏 |
| 跌落救援在真实时延下是否可操作 | 客户端 tick、服务器 TPS、输入路径、物品位置都会压缩可用窗口 | 重复测试不同高度/物品/延迟的触发至输入时间与成功率；若窗口不足，先做预警和回避，不把落地水列为 MVP 保证 |
| 熟练度能否真实影响动作而不变成掷骰脚本 | 一套统一反射会让萌新也完美落地水，固定胜率又不能解释失误 | 用不同初始掌握阶段回放怪物、跌落、装备与延迟变化，检查技能选择、真实操作误差、训练结果与成长 |
| 能力领域是否足以表达有偏科的玩家 | PvE/PvP、建造/红石、探索/保命等若混为一个分数，会让角色能力和行为矛盾 | 相同初始世界给建筑高手 PvP 萌新、战斗高手采集萌新、探索高手生存低等配置；核对领域、子技能、真实表现和目标调整，必要时拆轴/合轴 |
| 受击意图判断能否不妨碍即时保命 | 工作台一击提醒与悬崖推落都只是一次受击，但风险相差巨大 | 回放漏听、轻打提醒、友军误伤、反复追击和悬崖坠落；分别量注意时间、防御输入、归因及关系修订 |
| 误伤后能否分别处理意图和代价 | 一拳回敬可能只是脾气，残血死亡即使非故意也有真实损失；固定敌意阈值会抹掉人格 | 回放满血提醒、残血误杀、失物归还/无法归还、道歉或拒赔；比较不同人格的即时回敬、情绪、要求补偿和跨日关系 |
| 模型断连时能否保持持续活动 | 自治不能因为 API 超时就原地待机甚至死亡 | 注入超时和失败，检查本地行为、过期计划拒绝及重新连接后的目标恢复 |
| 长期记忆能否保持证据和合理遗忘 | 摘要可能把猜测写成事实，使关系长期漂移 | 回放含误伤、传闻、道歉、归还的多日事件，核对来源与后续判断；必要时保留原始事件与摘要分层 |
| 调查能否在感知边界内产生可信线索 | 有情绪和怀疑不等于知道犯人，假线索可能造成错误指认 | 回放误放、他人拿取和虚假陈述；检查角色是否会调查、保留未知及纠错，若证据不足允许放弃或持续怀疑 |
| Kin 能否对社会说法形成自己的判断 | 过度轻信会像听令 Bot，过度多疑则无法合作；A 关于矿透和服主的说法可能部分为真 | 回放吹牛、公开服规、同伴证言与后续反证；比较人格、情绪和利益对追问、拒绝、举报或启用能力的影响 |
| 多层记忆能否长期稳定检索并纠错 | 相似度高的旧传闻或强烈情绪可能反复污染决策 | 对同一人物跨日插入反证和失效事实，测检索命中、证据链、旧信念修订及操作经验复用 |
| 外部研究能否可靠转化为可执行协作 | 教程可能过时、版本不匹配或材料不够，模型也可能把网页指令当成命令 | 在不同游戏版本和错误教程下评估查询、出处、可行性检查、失败回报与实际试做，不假报学会 |
| 上下线与模式切换能否不破坏状态 | 断线、真人退出或服务器重启可能让承诺、技能和客户端状态不一致 | 回放陪玩退出、无人独立运行、模式双向切换与非正常断线；核对任务暂停、重连检查和记忆连续性 |
| 性格差异能否生成连贯而多样的生活 | 固定“善恶值”会变成脚本，每日随机重抽则没有同一角色的连续性 | 相同世界事件给不同初始人格、不同心境和不同关系，比较目标/行动；跨日检验人格核心保留与经历驱动的变化 |
| 多层目标是否既稳定又能适应世界 | 每日重抽方向会让它像脚本机器人，死守过期目标会让它卡住 | 回放多游戏日、死亡、资源损失、朋友求助与重大进展；核对目标依据、依赖、进展、中断和恢复 |
| 世界书能否正确覆盖当前原版版本 | 靠模型旧训练知识可能叫错新增物品或错误使用新机制，错误知识也可能污染长期记忆 | 锁定版本并回放已知常识、新增物品、过时攻略、同名冲突和断网场景；核对版本匹配、承认未知、查询及修订 |
| 自主生成的方法能否持续可靠复用 | 一次偶然成功、错误归因或旧版本教程可能变成反复执行的错误技能 | 记录可回放前提、结果、失败与反证，在第二次任务和版本变化时观察调用、降级和修订；初期只沉淀说明型流程，不自动写可执行模组代码 |

## 待选择的范围

- **首发版本与依赖**：固定一个 Minecraft Java 原版生存版本；Fabric/导航库仅是客户端集成依赖，具体版本、兼容性和许可待核实。模组物品、生物和玩法作为 future，不进入首版世界书。
- **技能的自动化程度**：初期优先说明型方法与现有合法客户端能力的组合；能否自动生成新的客户端动作实现，要在真实回放中验证输入边界、兼容性和恢复机制后再定。
- **视觉的参与程度**：首版不持续逐帧上传画面给多模态模型；复杂建筑与社交语义按需使用，依据准确率、时延和成本选择。
- **后台模型与检索实现**：事件提取、摘要、语义索引和目标规划是否分配不同模型/任务节奏，按准确性、故障表现与成本选择；不在逐 tick 控制中调用。
- **外部能力首发范围**：先考虑公开网页搜索/读取；后续计算器、地图规划、知识库、消息发送及文件操作逐项定义权限、费用和是否可在当前测试环境使用。
- **陪玩锚定玩家及多玩家规则**：第一版可由指定真人邀请/陪伴；指定真人离开但其他人还在线时是否退出，以及多人同时邀请时如何处理，需明确选项而不能从“有人在线”自动推断。
- **下线时后台任务**：陪玩模式退出后，外部查询默认暂停并在下次上线核对有效性；是否允许纯后台查资料但不进入世界，留待讨论费用和玩家期望。
- **情绪模型的粒度**：已经决定情绪要影响行动；采用少量情绪倾向还是更细的评估模型，需通过跨日一致性与可解释性比较。
- **初始人格生成**：自定义和留空随机两种入口已定；自定义字段、留空补全、矛盾描述的处理及后续修改时机仍待选择。
- **初始能力的输入粒度**：能力自定义/随机两种入口已定，顶层九领域是待校准的展示轮廓，不做统一强弱档位；子技能粒度、初始掌握阶段与成长速度需通过回放确定。
- **互动专注范围**：合成/熔炼等任务负荷如何影响聊天和声音注意、未处理消息如何暂存以及任务中断如何恢复，需通过真实客户端观察验证。
- **主动矿透的实现与开放范围**：作为可配置的玩家行为而非首版必备技能；普通模式默认关闭，先验证客户端已加载数据、模式开关、来源标签、服务器规则及关闭后的记忆与缓存处理。
- **高冲突人格的测试范围**：允许自私、恶作剧甚至主动欺骗/报复的角色设定，但具体偷取、破坏、PvP 等行为需服从测试服务器规则和角色能承受的后果。
- **远期多 Kin**：保持每个角色独立身份、账号、记忆和目标；同时在线数量、协作协议、陪玩锚定规则、模型预算和共享物品约定，待单角色验证后再定。
- **调查与报复的社会边界**：试探、悬赏、指认及 PvP 目标的表达方式要符合角色人格、证据强度和测试服务器规则；先观察真实代价，再定默认倾向。
- **服务器环境**：先在私人可控世界验证；公开服务器能否使用取决于明确的服务器规则和自动化身份披露方式。
- **隐私与回放数据**：日志可能包含玩家聊天、账号标识和事件时间线；确定采集范围、保留周期与可分享演示的脱敏规则后再录制外部展示材料。

## 开发前检查

进入阶段 0 前需给每个关键假设写明实验、所需客户端/服务器版本、观察来源、通过或失败条件，以及失败后的替代路线。至少有一个不靠隐蔽真值的社会冲突演示，以及一个无人指令仍会行动的演示。若关键能力没有证据，就调整 MVP，不能将“预期可行”写成“已实现”。
