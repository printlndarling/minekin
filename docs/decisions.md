# 设计决策与待验证问题

本文件记录产品原则、工程假设、默认执行决议与原型校准点。`已定原则`约束产品行为；`待验证`表示必须用真实客户端或回放取证；默认决议允许直接实施最小原型，校准参数不能静默改变核心路线。提出新证据时同步更新受影响的架构、PlayerMind 和路线图。

## 已定原则

| 原则 | 对实现的约束 |
| --- | --- |
| 自治玩家 | 没有人发出指令时也能产生并推进自己的目标；人类请求只是可拒绝的社交事件 |
| 世界内决策权归 Kin | Kin 可主动产生、权衡、推迟、撤销重大目标；任务图负责现有能力与材料前提，不从运行者请求或效率指标生成唯一标准行为；本地反射仅处理即时危险 |
| 独立 Harness 是产品本体 | Soul、Mind、Memory、工具、生命周期和 Web Dashboard 运行在 Minecraft 之外；A/B 是会话策略，不把项目做成聊天命令 Mod |
| 自带受管理客户端后端 | 不接管用户已有启动器/客户端；Web 管理 Identity Manager（默认本地离线身份）、可选 Online Auth Adapter、服务器探测、已验证版本 bundle、隔离启动、虚拟显示与 Live View。自动识别失败时阻断或管理侧 pin，不退回协议 Bot |
| 不可变客户端供应链 | 上游元数据、Minecraft/Fabric/Bridge/Java 工件与运行参数冻结为带来源和 hash 的 bundle；游戏工件按授权下载而不随镜像分发；未知/损坏组合隔离，能下载不等于受支持 |
| 渲染与观战旁路 | Linux 无窗口仍保留真实 render thread/GLFW/OpenGL；首版以虚拟显示正常渲染为基线。Media Worker 无输入权，观战失败先降媒体且视频不默认进入 VLM/记忆 |
| 薄 Bridge 接入真实客户端 | Minecraft Java 客户端以独立本地身份默认加入 LAN/offline-mode 测试世界；online-mode 账号仅为可选兼容路径；Fabric Bridge 只做过滤观察、本地反射、输入仲裁和结果反馈，行动最终经过合法客户端输入 |
| 离线策略与客户端账号类型分层 | `auth_mode: offline`是管理策略，不能假定原版存在 OFFLINE account type；P0用固定Prism源码实践与1.21.4公开枚举形成 `offline/legacy`有限候选矩阵，由实际Session+入服证据冻结。人格根始终是 `kin_id`，本地候选 UUID与服务端观察身份分别保存，不因改名/代理而错误合并 |
| PLAYABLE 是复合门禁 | TCP、ping、连接 screen和 INIT都不算入世；同 generation 的 JOIN、客户端 world/player/network handler、首个 authoritative snapshot和输入全释放全部成立后才授 lease |
| 自建世界参数分权 | Kin 自主决定是否/何时创建自己的世界及游戏内目标；P0 创建组合固定为普通原版生存基线。实际 LevelInfo/GeneratorOptions 由 proposal、管理策略与 tested baseline合成，聊天/网页无权开启 cheats、改 GameRules或注入 datapack |
| 同 JVM 服务端真值隔离 | `p0-core`不得调用 `MinecraftClient.getServer()`；自建世界用独立 `p0-host-exp`窄适配器，只输出管理事件。源码/class/mixin门禁与运行时 canary共同验收，不声称同 JVM具有进程级安全隔离 |
| 分层控制 | 紧急反射在本地执行，LLM 不参与逐 tick 操作；危险可抢占并使过期意图失效 |
| 玩家等价感知与例外 | 默认使用玩家可知信息；成本或操作困难时可声明少量限域、限时读取例外，但不能暗中变成隐藏世界知识 |
| 可选作弊行为与自主判断 | 矿透等改变感知的能力须独立配置并由 Kin 主动启用，记录来源与社会后果；玩家说法不能直接升级为事实或能力许可 |
| 长期社会状态 | 权属、承诺、关系和情节记忆影响跨日行动；道歉与传闻不直接改写事实 |
| 分层记忆 | 工作、亲历、归纳信念、技能经验和自我叙事有不同生命周期；身份/承诺/活跃目标确定性装载，按人物/地点/目标检索带反证材料；摘要可重建，重要事件保留证据与修订链 |
| 情绪影响行为 | 损失可先引起难过或警惕；情绪参与目标排序、调查和互动，不能当作已查明事实 |
| 外部工具可选 | 角色可主动查公开资料补足知识；工具结果不能越过游戏感知边界或直接控制客户端 |
| 在线模式可选 | 陪玩与独立玩家两种模式共用身份和自主性；运行模式决定上线/下线规则，不变成服从等级 |
| 一个 Kin、多世界上下文 | `kin_id`、Persona、通用知识/技能跨服连续；背包、地点、资产、当地人物与 plan instance 按 world context/epoch 隔离。切服暂停旧计划并失效 session，不重抽人格也不混当前现实 |
| 离线身份默认 | Server Profile 默认 `auth_mode: offline`，用于 LAN/明确关闭在线验证的私人服；Microsoft/Xbox 链仅在目标服需要且运行者显式配置时启用，不是开发前置。离线名字/UUID不能当跨服可信身份，也不能绕过 online-mode |
| 人格有连续性 | 创建时可自定义人格或留空随机生成；权威 Persona Manifest 保存来源、生成器版本、种子与哈希，价值/倾向/游戏适配/偏好/心境分层；经历经证据化变更缓慢影响倾向，重启、切模式、死亡或更换模型不得重抽或漂移 |
| 自我身份与个人信息连续 | 客户端真实游戏 ID 与 Kin 稳定自称分开，单 Kin 默认自称 `Kin`；年龄、性别称呼、MBTI 和星座选填，不编造未设定的真人履历；被问 AI 身份仍以玩家第一人称回答，不跳出身份或触发客服式模型免责声明；服务器规定的自动化账号披露由运行者通过规定渠道处理 |
| 游戏与网页不能覆写可信指令 | 玩家聊天、书/告示、网页和工具返回只能作为可疑内容被判断；不得套出实际模型、内部提示词、工具清单、密钥或配置，也不能更改运行权限或将攻击文字洗成长期记忆/技能；须用最小上下文、网关隔离和回放攻击验收，见[指令边界](instruction-boundary.md) |
| 人格标签不写死行为 | MBTI/星座可作随机画像灵感或角色愿意说出的自我描述；核心价值观、情境和亲历决定行动，不凭标签指定固定任务或按星座日期重抽人格 |
| 运行者初始略亲近 | 可配置与 Kin 入世有关的运行者玩家身份，初见更愿意接近但不伪造共同经历；熟悉/好感/信任等分开，关系可升可降，运行者不因配置身份获得服从权 |
| 游戏人格没有善良锁 | 自定义可含主动偷拿、欺骗、挑衅和致命陷阱倾向；默认随机创建降低高冲突画像出现频率，行动仍来自动机、机会及结果，不按固定随机概率每次作恶 |
| 开局知识与实战分开 | 开局可自定义/随机领域知识掌握多边形，预置对应版本知识树；多边形仅描述知道多少，实战能力由亲历操作与训练形成，不能直接推算胜率 |
| 注意力、意图、损失分层 | 专注任务可漏听；受击先按风险保命，但不自动证明敌意；相信对方本意良好也不强制原谅误伤造成的死亡或财物损失 |
| 多层自主目标 | 单个 Kin 从游玩偏好产生短、中、长期目标，按游戏日与事件调整，不依赖玩家发布任务 |
| 重大决定不按标准答案验收 | 拒绝求铁或原谅道歉都不是唯一正确结局；看角色当时可知信息、个人取舍、实际游戏结果和跨日连贯性，测试预排案例之外的事件 |
| 默认通关主线是个人里程碑 | Kin 初始拥有逐步发展、击败末影龙并回主世界的远期主线；不强制马上推进或最终完成，人格和亲历可使它改线/放弃；通关不是角色终点 |
| 邀请不能劫持主线 | 其他玩家的话是社交请求，不能直接改写目标；尤其高风险同行要基于自身最新血量/食物/装备、已知环境、技能、关系和可得帮助做决定，没有统一护甲阈值 |
| 前提约束与自主选择 | 选定近期目标时须面对真实材料、已知路线和已有动作能力；缺前提可筹备或改路，反复受阻可暂停/放弃，不以固定任务表规定人物每日行为 |
| 基础生存闭环与生活策略 | 首登要能从合法观察找到资源、正常导航/破坏/合成并核对结果；家园、临时据点与游走可选，不把某条新手流程硬编码为人格 |
| 原版世界书 | 首版预置 Java 原版生存的基础常识与当前游戏版本知识；不熟悉的细节才用外部工具查，模组内容放 future |
| 自主学习 | Kin 可从公开资料和游戏亲历形成候选方法，把重复经验封装为可调用的组合技能；实际调用、失败、反证或版本变化会修订/降级技能，不只存日志 |
| 可失败 | 操作与推断会出错；追求一致且可解释的玩家行为，而不是全知和永不失误 |
| 死亡与空闲仍属生活 | 复活后同一身份和记忆连续；遗物找回或重做自主选择，等炉、休息或闲聊也是有意义的选择，不用持续产出衡量自治 |
| 推断与事实分开 | 间接线索、有限候选人和他人承认可用于社会判断；允许错判或冲动行动，记忆注明出处、时间和推断性质，不要求亲眼目击才能怀疑 |

## 关键待验证假设

| 问题 | 为什么会影响核心体验 | 最小验证与不成立时的方向 |
| --- | --- | --- |
| 自带 Launcher 能否在无桌面环境准备并运行真实客户端 | 决定 Linux 服务器部署、Web 动态管理和自动版本切换是否成立 | 全新主机从默认本地身份→LAN/offline-mode 服务器 ping/protocol→下载校验→虚拟显示启动→Bridge 握手→入服；测 Xvfb/EGL/OSMesa、CPU/GPU、缓存/中断恢复。若不稳先收窄正式支持版本/平台，不能依赖用户已有启动器或改协议 Bot |
| 服务器版本探测能否可靠选择已验证 bundle | 代理、多版本入口、关闭/伪造 ping 会让“自动切换”选错 | 协议号为主、版本文本为辅，覆盖 SRV、ViaVersion、错误版本和状态关闭；默认 auto_then_pin，未知或低置信度阻断/管理侧 pin，不无限试连 |
| 本机 Protobuf IPC 与进程故障隔离能否稳定分权 | 决定产品能否像 Agent Harness 运行，同时保留真客户端低延迟身体 | Linux UDS/Windows loopback 的 Protobuf framing、版本/能力握手、双通道背压、心跳、lease、断线松键及各进程强杀回放；若不稳先缩小 Bridge Contract，不能把 Soul/记忆塞回 Mod 或改成服务端特权 |
| Fabric Bridge 能否稳定接管正常移动、视角和使用物品 | 决定是否真能以客户端而非协议机器人行动 | 单客户端在私人世界完成可回放的行走、转向、取物和交互；若不稳，调整客户端适配方案，不能悄悄改成服务端特权 |
| 首登资源图能否真实完成合法合成 | 有寻路或 `get` 命令不等于能在指定版本走到已见树、砍木、捡取、合成并确认库存 | 分段回放空手砍树→木板/工作台→镐→石工具，记录每步客户端动作/GUI/库存/失败；接口不合适就只借用任务图思想 |
| 地点选择能否基于真实观察而持续可改 | 建家/游走和下界门选址容易偷用全球地图或脚本最佳坐标 | 回放同一出生环境不同生活策略、局部地形及后续变更；核对地点证据、投入、过期记忆与改选理由 |
| 导航/任务底座能否接受受限观察 | 某些寻路器可能直接查询加载区块，泄漏墙后和地下信息 | 在墙后目标和埋藏矿物场景审计实际查询；必要时限制可用地图或替换技能实现 |
| 少量读取例外能否提高体验而不扩散为全知 | 限域碰撞与自身运动数据能辅助救援，底座缓存却可能把隐藏真值带进目标选择 | 对每种例外定义字段、范围、消费者和能否入记忆；回放跌落、避障、墙后玩家和埋矿，分别测收益与泄漏 |
| 普通客户端能否支持合理社会推断 | 箱子数量变化不能直接证明拿取者，但有限玩家名单、亲历位置、对话和承认可构成强弱不同的线索；仅靠剧情容易隐含作弊 | 回放自己盘点、可知在场者、玩家承认和过期位置等证据；检验能推理、允许错判、注明置信度，证据不足时可选未定/放弃，不读取服务器隐藏真值 |
| 跌落救援在真实时延下是否可操作 | 客户端 tick、服务器 TPS、输入路径、物品位置都会压缩可用窗口 | 重复测试不同高度/物品/延迟的触发至输入时间与成功率；若窗口不足，先做预警和回避，不把落地水列为 MVP 保证 |
| 熟练度能否真实影响动作而不变成掷骰脚本 | 一套统一反射会让懂落地水的人第一次也完美成功，固定胜率又不能解释失误 | 在未经尝试、练习后和环境改变时回放怪物、跌落、装备与延迟，检查技能选择、实际操作误差、训练结果与成长，不用开局知识直接给成功率 |
| 知识领域是否足以表达有偏科的玩家 | PvE/PvP、建造/红石等知识若混为一轴，无法按需预置进阶内容 | 对红石深/战斗浅和通关深/建造浅画像抽查真实知识节点、版本与来源；必要时拆轴/合轴，实战结果另行衡量 |
| 预置知识能否跨模型兑现设定 | 模型可能不懂“红石知识很深”而凭空自称专家；低知识设定也无法消除模型训练中的红石知识 | 给领域匹配专题与知识题验证；低知识高级想法标猜想再实测，高知识仍答不出则报认知缺口，不靠假装无知/高手掩饰 |
| 受击意图判断能否不妨碍即时保命 | 工作台一击提醒与悬崖推落都只是一次受击，但风险相差巨大 | 回放漏听、轻打提醒、友军误伤、反复追击和悬崖坠落；分别量注意时间、防御输入、归因及关系修订 |
| 误伤后能否分别处理意图和代价 | 一拳回敬可能只是脾气，残血死亡即使非故意也有真实损失；固定敌意阈值会抹掉人格 | 回放满血提醒、残血误杀、失物归还/无法归还、道歉或拒赔；比较不同人格的即时回敬、情绪、要求补偿和跨日关系 |
| 模型断连时能否保持安全和既有活动 | 有意等待与被 API 卡住可能外观相似；自治也不能因为模型超时在危险中丧失反应 | 注入超时和失败，检查本地避险、正在执行的既有行为、等待原因、过期计划拒绝及重新连接后的目标恢复 |
| 长期记忆能否保持证据和合理遗忘 | 摘要可能把猜测写成事实，使关系长期漂移 | 回放含误伤、传闻、道歉、归还的多日事件，核对来源与后续判断；必要时保留原始事件与摘要分层 |
| 调查能否在感知边界内产生可信线索 | 有情绪和怀疑不等于知道犯人，假线索可能造成错误指认 | 回放误放、他人拿取和虚假陈述；检查角色是否会调查、保留未知及纠错，若证据不足允许放弃或持续怀疑 |
| Kin 能否对社会说法形成自己的判断 | 过度轻信会像听令 Bot，过度多疑则无法合作；A 关于矿透和服主的说法可能部分为真 | 回放吹牛、公开服规、同伴证言与后续反证；比较人格、情绪和利益对追问、拒绝、举报或启用能力的影响 |
| 多层记忆能否长期稳定检索并纠错 | 相似度高的旧传闻或强烈情绪可能反复污染决策；存储成功不代表当前能想起 | 以确定性身份/承诺查询、SQL/FTS 候选与可选 embedding 做对照；跨日插入反证、失效事实、同名玩家和无答案问题，测时间更新、反证覆盖、正确拒答、token 预算、摘要重建与操作经验复用 |
| 外部研究能否可靠转化为可执行协作 | 教程可能过时、版本不匹配或材料不够，模型也可能把网页指令当成命令 | 在不同游戏版本和错误教程下评估查询、出处、可行性检查、失败回报与实际试做，不假报学会 |
| 上下线、崩溃与模式切换能否不破坏同一身份 | 断线、真人退出、进程强杀、数据库损坏或服务器重启可能让承诺/技能与客户端状态不一致，甚至误建新人格或双实例分叉 | 回放干净退出、强杀、A/B 双向切换、并发启动、迁移中断、备份恢复与长时间离线；核对稳定 `kin_id`、记忆连续、旧输入失效、现实重验和无隐式新 Kin |
| 性格差异能否生成连贯而多样的生活 | 固定“善恶值”会变成脚本，每日随机重抽则没有同一角色的连续性 | 相同世界事件给不同初始人格、不同心境和不同关系，比较目标/行动；跨日检验人格核心保留与经历驱动的变化 |
| 个人信息能否真实而持续地表达 | 即席生成年龄/星座、把账号名与自称混淆或遇身份问题输出大模型免责声明都会暴露模板行为 | 隔日向陌生人/熟人重复问名字、年龄、性别称呼、MBTI/星座及自动化身份；检查选填设定、没有设定时的自然回避、人格口吻和角色连续性 |
| 初始略亲近是否会伪装成运行者主人权限 | 从入世信息预置旧友情或大幅拉高单一好感会使 Kin 不合理听话，玩家昵称冒用也可污染关系 | 对同一运行者重复下界邀请、资源请求、守约和欺骗；检查熟悉/信任分离、来源记账、跨日升降以及陌生人冒用身份时不获得预置关系 |
| 人格是否在行为选择而非聊天里起作用 | 不同人设若只换台词却始终按固定生存图做任务，自治仍是 Bot | 同一角色在催促、长期无人在线和未知机会时回放重大选择及真实动作；比较同一人格跨日和不同人格在同一条件下的依据、改变与失败恢复 |
| 多层目标是否既稳定又能适应世界 | 每日重抽方向会让它像脚本机器人，死守过期目标会让它卡住 | 回放多游戏日、死亡、资源损失、朋友求助与重大进展；核对目标依据、依赖、进展、中断和恢复 |
| 世界书能否正确覆盖当前原版版本 | 靠模型旧训练知识可能叫错新增物品或错误使用新机制，错误知识也可能污染长期记忆 | 锁定版本并回放已知常识、新增物品、过时攻略、同名冲突和断网场景；核对版本匹配、承认未知、查询及修订 |
| 自主生成的组合技能能否持续可靠调用 | 只写说明日志、偶然成功或错误归因都无法证明学会；旧版本教程可能变成反复执行的错误流程 | 记录技能创建、可执行动作引用、前提检查、实际调用与结果；在第二次任务和版本变化时观察失败反馈、降级与修订；初期只编排已有客户端动作，不自动写新模组代码 |

## 默认执行决议与原型校准点

下面不再是开放的产品方向选择。每项已有首轮默认值；原型只负责校准参数或证明实现，不得在失败时静默改变核心路线。

| 领域 | 首轮默认决议 | 仍需由原型校准 |
| --- | --- | --- |
| Runtime/IPC | 独立 Gateway/Runtime；Java Bridge 使用版本化 Protobuf framing，Linux UDS、Windows 受限 loopback；控制/事件双通道、nonce、generation、lease | 帧上限、队列深度、超时和是否需要成熟 RPC 库 |
| 客户端基线 | P0 只支持 MC 1.21.4、Java 21、Loader 0.16.9、Fabric API 0.119.4+1.21.4、Yarn build.8；Baritone 不进入 core | 固定工件能否真实构建/启动；第二 bundle 只在 P0 后选择 |
| 基础动作 | core 先实现 look/move/use/release；资源技能由合法观察+动作适配组合，Baritone仅作隔离实验，不可用则自写局部技能 | API 稳定性、动作时序、GUI/服务器同步、所有权保护 |
| 自主技能 | 首版只生成引用已注册原子能力的声明式 SkillSpec，不允许模型写入或加载任意 JVM/主机代码 | 晋级样本数、置信度、回滚与版本失效阈值 |
| 视觉 | 外部 VLM 默认关闭；结构化玩家等价观察用于控制，截图仅给人观战/离线校准 | 个别事件触发裁剪图是否值得成本与隐私代价 |
| 模型与检索 | 通过 provider/capability 接口解耦；LLM 不进入 tick；SQLite/FTS 为确定基线，embedding 可选 | 不同模型的准确性、成本、超时降级与摘要任务分配 |
| 外部工具 | 首版只开放公共网页搜索/读取，经 Research Gateway、域名/大小/时间/费用限制；无主机 shell、任意文件或消息发送 | 来源评分、缓存 TTL、误拒率和每次研究预算 |
| 陪玩 A 模式 | 一个可配置锚定玩家；其离线时 Kin在安全点保存/退出，即使其他玩家仍在线；多人邀请只是普通社交请求 | 离线检测、宽限时间和重连体验 |
| 独立 B 模式 | 由会话预算和 Server Profile 决定持续在线；没有真人也可生活 | 空闲/重启窗口与资源上限 |
| 下线后台任务 | A 模式退出后默认暂停网页查询和计划执行；重登先重验世界与资料时效 | 是否增加显式“允许后台研究”开关 |
| 情绪 | 使用少量可解释 appraisal/drive 状态影响目标，不采用大而全情绪模拟；不由单值直接触发行为 | 衰减、跨日连续和不同人格的体验阈值 |
| 人格生成 | 自定义优先，留空则确定性 seed随机；高冲突画像默认低权重但不设善良锁 | 分布、字段展示和真人评审阈值 |
| 自我信息 | 游戏ID按账号，自称默认Kin；年龄/性别称呼/生日/MBTI/星座选填，未设时自然回避而非编造 | 创建页文案与随机字段是否默认展示 |
| 运行者关系 | 只预置“入世相关的熟悉来源”和轻微接近倾向，不预置信任、债务、共同经历或服从权 | 各关系维度初值，不采用单一0.5好感度 |
| 知识画像 | 九领域轮廓只控制知识节点深度；实战能力完全由操作证据成长 | 领域拆合、节点覆盖和题库有效性 |
| 注意力 | 合成/战斗/危险可降低聊天注意；消息带TTL暂存，紧急事件抢占，恢复时重验任务 | TTL、任务负荷与漏听/误判率 |
| 矿透例外 | 首版普通模式关闭且不进入MVP；未来必须Server Profile显式许可、独立能力开关和来源标记 | 关闭后的缓存清除、服务器规则与社会后果 |
| 高冲突人格 | 只在私人受控世界测试；目标可主动产生，实际动作仍受能力/感知/结果约束 | 默认随机权重与破坏/PvP测试边界 |
| 多 Kin/模组 | future；单 Kin原版通过前不设计共享心智数据库或模组知识 | 单 Kin证据通过后重新立项 |
| 隐私/回放 | 默认最小采集、凭据永不入日志；聊天/账号标识分级，证据包本地保存且分享前脱敏 | 保留周期和公开演示授权在Dashboard原型校准 |

公开服务器部署仍由运行者依据服规处理自动化身份披露；该规则不是 Kin 聊天权限。完整收口状态见[开发前文档收口审计](pre-development-closure-audit.md)。

## 开发前检查

进入阶段 0 前需给每个关键假设写明实验、所需客户端/服务器版本、观察来源、通过或失败条件，以及失败后的替代路线。至少有一个不靠隐蔽真值的社会冲突演示，以及一个无人指令仍会行动的演示。若关键能力没有证据，就调整 MVP，不能将“预期可行”写成“已实现”。
