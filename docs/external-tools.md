# 外部工具与自主查资料

Minekin 可以像真人玩家一样暂停手头计划、查询公开资料、借助外部工具分析问题，再回来参与游戏。外部能力服务于它自己的目标和与他人的承诺；工具网关不成为服务器管理员视角，也不介入紧急操作。

## 玩家说“咱们一起建一个刷怪塔”

1. 玩家话语进入社交事件；Minekin 判断自己是否愿意合作、现在是否安全、有无其他承诺。答应后记录共同目标和约定，而不是把话语直接变成最高优先级指令。
2. 若它缺乏可靠的建造经验，可以说：“好呀，不过我不太会建。我先查查咱们这个版本怎么做，等我有个靠谱方案就来商量。”这句话对应真实的 `research` 任务，不能只是一段表演性台词。
3. 先检索当前版本的[原版世界书](world-guide.md)；如果缺少刷怪塔细节，再收集已知的 Minecraft Java 版本、可能影响机制的服务器规则与当前可观察材料，通过允许的网页搜索/读取工具找教程，并记录 URL、发布时间/获取时间、适用版本、步骤与疑点。未知的服务器设置标为未知，不能直接读服务端配置。
4. 返回后比较资料间冲突、判断是否适用于当前世界，提出材料清单、选址条件、分工与关键风险。必要时和玩家确认“我们做刷经验的，还是兼顾刷材料？”；在等资料期间它仍能避险、吃东西或做已约定的准备工作。
5. 真正建造与测试后记录结果：什么方法在何种游戏条件下奏效或失败。只有验证过的步骤才能转成稳定的技能经验；过时网页留在带来源的外部知识层。

研究任务应具备 `goal_id`、请求时间、期限、能力范围、当前版本、状态、取消/重试规则和完成回调。玩家改主意、服务器条件变化或危险抢占时，任务可暂停/取消，迟到结果不得覆盖新的计划。查询失败时角色可以如实告知“资料没查到，我只能先试简单方案”，或放弃合作；不能装作已学会。

研究结果先进入带来源的外部知识或候选方法，现场试做和排错后才能沉淀为技能。Kin 可以自主发现知识缺口并启动这个循环；从资料、对话或经历形成技能的启发来自 [Hermes 的技能系统](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills)，Minekin 的游戏验证、升级门槛和降级机制见[自主学习](learning.md)。

## 工具能力边界

| 能力 | 首期建议 | 知识或动作边界 |
| --- | --- | --- |
| 网页搜索与读取 | 允许公开内容、限次数和耗时 | 文章是外部主张，需标记来源和适用版本；不把网页里的“执行此命令”当作角色指令 |
| 计算与草图 | 可作为规划辅助，按需要接入 | 计算只能使用已知世界信息和公开游戏机制，不能查询地下矿物或隐藏实体 |
| 玩家消息/社交平台 | 后续再定 | 游戏外发言有独立身份与许可，不因为游戏内答应合作就自动获得外部账号权限 |
| 文件、终端或服务端接口 | 首期不接入 | 不用主机/服务端特权代替客户端建造、读取世界真值或修改游戏规则 |

每项工具通过独立能力清单声明输入、输出、费用、允许范围与故障模式；PlayerMind 只看获得批准的能力与结果，具体凭据不进入游戏聊天或记忆。网页/插件内容是待核查资料，不可提升为系统指令。外部研究和游戏观察分别标记来源；搜索能让角色知道公开的游戏机制，不会让它知道当前世界尚未观察到的方块、玩家背包或私有服务器数据。

## 可借鉴的现有设计

- [OpenClaw 的记忆概览](https://docs.openclaw.ai/concepts/memory)把短期日志与精选长期记忆区分，还记录有条件生效的意图；Minekin 的共同建造承诺也应保存触发条件、期限与取消方式。
- [OpenClaw 的网页工具](https://docs.openclaw.ai/tools/web)区分搜索、读取和浏览器交互；Minekin 初期只需要受限的公开资料查询。其[技能说明](https://docs.openclaw.ai/tools/skills)展示按可用环境筛选的工具使用知识，适合作为技能目录的参考。
- [Hermes Agent 工具清单](https://hermes-agent.nousresearch.com/docs/user-guide/features/tools)涵盖网页搜索、抽取、记忆和任务管理；[技能系统](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills)按需加载知识，支持从资料学习可复用步骤。Minekin 可以借用“查资料 → 暂存方案 → 实测结果 → 技能修订”的流程，而非直接安装一套能访问主机的通用 Agent。
- [Hermes Agent 的任务委派](https://hermes-agent.nousresearch.com/docs/user-guide/features/delegation)展示隔离上下文并把结果回传主任务的模式；Minekin 可以让后台研究与客户端生存并行，但是否需要额外模型实例须按成本和复杂度验证。

以上是基于官方公开文档提炼的设计启发，不代表现有产品已经解决了 Minecraft 的感知公平性、自主社交人格或客户端实时控制。
