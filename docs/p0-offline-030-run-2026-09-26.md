## 6. 反证：这句断言既能答「是」，也能答「不」

`evidence verify` 只认摘要，改一位字节得到的永远是 `ARTIFACT_DIGEST_MISMATCH`（本 bundle 也一样：
读数日志 §5 把副本的 `connection_state` 改成 `JOIN_SENT` 后，复判 rc=2 报
`ARTIFACT_DIGEST_MISMATCH:run-document.json, RUN_ID_MISMATCH`，规范卷同一 run 仍 `verified`）。
所以「判官不是空判」必须在**材料层**验，不是在字节层验。做法：读同一份 bundle 的封进去的材料
（`read_sealed_material`），一次只改一个事实，再用今天的 `offline-030.json` 判（读数日志 §4）：

| 编号 | 只改一个事实 | 判官的回答 |
| --- | --- | --- |
| P | 什么都不改（正对照） | `PASS observed=1/1 failures=[]` |
| D1 | 拿不到 Core 的账本（`ledger_readable=False` 且无事件） | `FAIL … :LEDGER_UNREADABLE` |
| D2 | 删掉那一行 `JoinObserved` | `FAIL … :JOINS_RECORDED:0` |
| D3 | 同一次 run 里出现第二行到达 | `FAIL … :JOINS_RECORDED:2` |
| D4 | 到达行的 `trust_class` 改成 `UNFILTERED` | `FAIL … :JOIN_ROW_NOT_ATTRIBUTABLE:BRIDGE/UNFILTERED` |
| D5 | `snapshots_admitted → 0` | `FAIL … :FIRST_SNAPSHOT_NOT_ADMITTED:NO_SNAPSHOT_ADMITTED` |
| D6 | `connection_state → JOIN_SENT` | `FAIL … :FIRST_SNAPSHOT_NOT_ADMITTED:CONNECTION_NOT_PLAYABLE:JOIN_SENT` |
| D7 | 服务端日志里那句 `joined the game` 抹掉 | `FAIL … :FIRST_SNAPSHOT_NOT_ADMITTED:JOIN_NOT_LOGGED` |
| D8 | `usercache.json` 里名字映射到别人的 UUID | `FAIL … :SERVER_IDENTITY_NOT_EXPLAINED:IDENTITY_UUID_MISMATCH:49918b3c-d10e-3517-b517-fb73232dbf29` |

八行各自只碰判据文档里点名的一个事实（`assert_case_evidence.py:3390-3417` 的三条记录 + 一条排除项），
P 与 §3 的复判给出同一个 PASS——判据没被改，改的是被判断的世界。

**这个对照的边界要说清**：它是**进程内**改材料（`dataclasses.replace` 之后调 `evaluate`），走的是封进去的
`read_sealed_material` 与今天的 case manifest，因此它证明的是「这句断言读这些事实时会判否」，
不是「活的读取路径在退化材料上也判否」（那条路径需要 `--server-directory` 与真实 overlay，本卡没有构造）。
这一条按 §7 记为本卡的 `Not-tested`。
