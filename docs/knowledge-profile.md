# 领域知识掌握多边形：开局知道什么

开局的多边形是 Kin 对 **Minecraft Java 原版生存公开知识** 的不同领域了解深度，而非“建造成功率”“PvP 胜率”或已经掌握的客户端操作。人格决定它想追求什么；领域知识帮助它理解玩法和提出方案；真实水平由进入世界后的观察、行动、练习与结果决定。熟悉通关流程却总死于怪物，与不知道流程但反应灵敏，都应能出现。

## 世界书与每个 Kin 的知识树

[原版世界书](world-guide.md)提供每个 Kin 都有的基本游戏语言、基础生存机制和所选版本术语；知识多边形决定启动时向角色**预置哪些进阶专题**、覆盖多深，并不移除客户端必须识别的安全或物品常识。初次创建时可用自然语言和各领域深度自定义、只设少数方向，其余补全，或留空生成有偏科的知识画像；预置目录、版本、来源、种子和最终内容持久保存。每次规划只检索本次相关的条目，不把整棵树塞入 LLM 上下文。

九个顶层知识方向是供讨论的初稿，深度具体落实在可核查的**知识节点**，按原型结果拆合，不把数字写进提示词就认定角色精通。

| 知识方向 | 节点示例 | 高深度意味着理解的内容 |
| --- | --- | --- |
| 生存机制 | 饥饿/血量、伤害、跌落、熔岩、急救选项 | 危险的前提和保命办法，不代表能做落地水 |
| 怪物与 PvE | 怪物习性、装备与附魔、环境/撤退策略 | 知道克制与战术，不代表打得赢 |
| 玩家 PvP | 武器、攻防节奏、走位策略、服务器公开规则 | 可讨论打法，不代表自己能执行 |
| 探索与地形 | 地形/维度、定位、探险准备、返回路线 | 知道怎么规划，不证明走得稳 |
| 资源获取 | 采矿机制、农牧、稀缺材料、公开生成规则 | 会设计采集路线，不预知本世界隐藏矿点 |
| 建筑设计 | 结构、选材、美感、施工方案 | 知道布局和设计原则，不证明能准确盖好 |
| 红石与自动化 | 红石元件、线路原理、刷怪条件、农场设计 | 有设计/排错知识，不代表会现场接线 |
| 制作与物流 | 配方、熔炼、装备进度、仓储和材料核算 | 熟悉工艺及成本，不证明背包操作熟练 |
| 多人玩法知识 | 公共游戏规则、分工、交易机制、常见协作方案 | 知道协作方式；愿意帮谁仍由人格和关系决定 |

每个节点至少有 `domain`、`topic`、`version_range`、`source`、`depth`、前提、正文/索引、核查状态；大方向深度是条目覆盖和解释层次的**可视化摘要**。预置知识不是这张世界的地形、他人背包或服主私有规则。若自定义“红石知识深”但缺乏对应版本的可靠资料，生成器不能只改变数值并让 Kin 自称专家；需补足资料并做知识题验证，缺口如实标注。[外部工具](external-tools.md)可在入世后补查未知细节。

## 大模型自身知道得多或少

LLM 的训练知识不等于角色被预置的知识，也不能从模型内部彻底擦去某条红石知识。Kin 对自己的认识以有出处的预置资料、亲历、别人陈述和查询结果为依据；模型在低知识方向突然想出正确高级方案时，可以将它标作**未经验证的猜想**，查资料或小试，不能伪称早已会做；也不必故意把正确答案改成错误台词来“装萌新”。知识是否真缺失、猜想是否越过角色所知边界，需要回放检测，不能声称提示词能完全控制模型参数知识。

高知识方向若模型实际不懂，检索版本匹配专题、实例和检查方法；模型仍不能正确说明/诊断时，该方向预置不足或认知实现失败，不能用空洞的人设证明“红石专家”。开局知识高也**不能直接授予实战能力**，后天的施工技能、操作稳定性和自我修订见[实际技能成长](ability.md)及[自主学习](learning.md)。

## 验收

在锁定版本后，分别给“红石高知识但未经施工”“红石低知识但模型训练很熟”“通关路线专家但战斗总失败”设置问答、规划、真实施工与失败复盘。检查预置知识节点与回答出处、未经证实的猜想标签、实际操作差异、经验积累及持续学习，而非用一条领域分数预测真实胜率。九轴若掩盖细节，按子节点拆分；若同一事实重复归两领域，调整索引，不硬保留多边形外观。
