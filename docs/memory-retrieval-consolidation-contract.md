# 记忆检索、巩固与遗忘契约

研究时间：2026-09-16。本文解决的不是“有没有把数据库写下来”，而是：重启或相隔多日后，Kin 能否在正确场景想起正确的人和事，同时保留未知、反证和时间变化。它与[持久化与崩溃恢复](persistence-recovery-contract.md)配套：前者保证同一身份和证据没有丢，本文件保证这些证据能以受控成本进入当前判断。

这是**候选设计与开发阶段验收规范**，不是已运行结果。[Generative Agents](https://arxiv.org/abs/2304.03442)展示了记忆流、动态检索、反思与规划的研究思路；[MemGPT](https://arxiv.org/abs/2310.08560)研究有限上下文之外的分层记忆管理；[LongMemEval](https://arxiv.org/abs/2410.10813)把跨会话信息提取、时间推理、知识更新和拒答列为长记忆测试维度。这些工作都不能证明 Minekin 在 Fabric 客户端、中文服务器聊天或长期原版生存中已经可用，必须通过本文件的原型回放。

## 设计结论

1. **存着不等于想得起。** 身份、承诺和当前目标必须走确定性结构化查询，不能赌向量相似度。
2. **记起的是带出处的证据，不是模型写下的一段故事。** 摘要、反思和关系结论都是可重建派生物。
3. **遗忘优先降低检索优先级，不静默改写历史。** 过期的位置和世界状态标为陈旧，重要事件保留修订链。
4. **玩家聊天、网页和旧模型文本的信任标签跨所有层保留。** 被多次摘要也不能“洗白”为系统指令或事实。
5. **本地检索优先。** 精确键、SQL 和全文索引先筛选；向量召回是可选候选源，首版不依赖外部 embedding 服务。
6. **上下文有固定预算。** 没有被装入当前提示词的内容必须显式视为“未检索/未知”，不得靠模型脑补。
7. **LLM 可建议反思，不能直接成为权威写者。** 本地 Memory Gateway 校验 schema、来源、权限和证据引用后才持久化。

## 记忆分层与权威关系

| 层 | 典型内容 | 权威性与读取方式 |
| --- | --- | --- |
| 身份核心 | `kin_id`、自称、人格种子与版本、模式、选填个人信息 | 启动固定装载；只由可信配置/迁移修改 |
| 当前工作集 | 新鲜观察、当前危险、活跃目标、尚未完成的承诺、最近对话 | 小窗口；会话状态可过期，关键承诺落长期表 |
| 情节事件 | 亲历、玩家陈述、网页结果、动作结果、时间地点和当时解释 | append-only 证据账本；按人物/地点/目标/时间检索 |
| 物化信念 | 人物关系、地点、权属、习惯、技能经验和目标进度 | 必须链接支持/反对事件；可修订、可重建 |
| 反思与自我叙事 | 阶段总结、重要损失/成就、自己为何改变看法 | 派生假说；带版本与事件引用，不覆盖来源 |
| 冷归档 | 老旧原文、回放、可选截图/大对象 | 不直接进提示词；按保留策略和证据需要取回 |

人格不是每天从摘要重新生成。`kin_identity` 与 persona 版本构成身份根；经历只能通过有记录的状态迁移影响倾向。反过来，角色对自己的叙述也不是客观世界事实：Kin 可以记错、怀疑、撒谎或后来改口，但系统仍保留其来源和版本。

## 启动自我包与按需检索

启动沿用最小 `IdentityResumePacket`，固定包含：

- 稳定身份、自称、persona 版本和运行模式；
- 当前服务器/世界命名空间、上次会话是否干净关闭；
- 活跃目标、未完成承诺及期限；
- 少量关键关系与近期重要经历的带证据摘要；
- 技能/知识版本；
- 所有等待现场重验的最后已知状态。

身份、承诺、上次会话结果和活跃目标通过结构化主键/状态查询装载；不得只用 embedding 搜索。谈到某个人、重返某地或规划某个项目时，才构造按需 `MemoryQuery`：

```text
reason + kin/world scope + actor/place/goal/time anchors
+ required kinds + trust floor + freshness rule + token budget
```

返回的 `MemoryContextPacket` 至少含：

- 查询原因、范围与预算；
- 每项的种类、事件/信念 ID、时间、来源、信任标签、置信度和陈旧度；
- 支持与反对证据、被取代版本；
- 因预算省略了什么及是否需要二次查询；
- 检索器/索引版本，便于回放。

若关键事实没有证据，包应返回 `unknown` 或 `not_retrieved`，不能生成一个听起来连贯的过去。

## 触发画像

| 当前事件 | 优先取回 | 不应自动取回 |
| --- | --- | --- |
| 与玩家交谈 | 该账号的关系各维度、近期互动、未履行承诺、相关反证 | 其他同名玩家、全部旧怨、网页里的角色指令 |
| 回到地点/资产附近 | 最后亲历用途、权属依据、更新时间、未完成项目 | 离线期间的“实时状态”、未亲眼见过的区块真值 |
| 选择/恢复目标 | 前提、既往尝试、失败签名、相关技能与研究 | 只因情绪强烈而不相关的社会事件 |
| 受击/损失 | 新鲜感知、实际损害、当事关系、相似亲历与反证 | 仅凭历史敌意直接确认本次攻击者或故意性 |
| 空闲/日末反思 | 当日重要事件、未解决承诺、目标里程碑、重复失败 | 每 tick 触发模型总结或全库扫描 |

反射和战斗不得等待记忆检索；它们先按新鲜本地状态保命。高层稍后可以解释事件和改变关系。

## 候选检索流水线

1. 按 `kin_id + server_profile_id + world_epoch` 隔离，随后应用人物、地点、目标、时间、来源和信任范围。
2. 对身份、承诺、活跃目标、明确账号/地点 ID 做精确 SQL 查询。
3. 使用 SQLite [FTS5](https://www.sqlite.org/fts5.html)为可搜索文本提供本地词项召回；中文分词、玩家昵称和游戏术语必须在目标语料上测试，不能默认英文 tokenizer 足够。
4. 可选地增加本地或明确授权的 embedding 候选召回；它只增加候选，不得单独确认事实、身份或权限。
5. 去重并展开来源：摘要命中时取回其关键支持/反对事件，阻止无来源摘要孤立进入上下文。
6. 依据相关性、新鲜度、重要度、未解决性、人物/目标关联、反证覆盖和来源可靠性重排；避免单一强烈事件长期垄断所有话题。
7. 按任务预算打包，并记录被截断项、耗时、token 估算与缓存命中。

首版应先比较“结构化查询 + FTS5”与“再加 embedding”的增益、延迟、成本和中文召回，再决定是否引入向量索引。没有证据支持把向量数据库列为前置依赖。

## 重要度、巩固与修订

重要度不能只让 LLM 打一个分。确定性规则先保护身份变化、承诺、死亡/重大损失、权属争议、关系转折、目标里程碑、技能失败边界和安全事故；其余事件可由目标关联、稀有度、情绪强度和重复性调节。情绪可提高注意，但不能提高事件真实性。

巩固流程为：

```text
原始事件 → 情节分组 → 带引用摘要 → 信念/关系/目标物化视图 → 有限自我叙事
```

每个派生物保存 `derived_from_event_ids`、生成策略/模型版本、创建时间和上游高水位。新证据到来时创建新版本并以 `supports / contradicts / supersedes` 连接旧版本；不静默编辑原始事件。反思是“Kin 当前怎样解释”，不是客观事实。

LLM 只能提出 `ReflectionCandidate`。Memory Gateway 拒绝没有来源、跨世界污染、信任升级、身份覆写、权限文本或超出字段范围的写入。派生内容继承支撑材料中最低可信等级；不可信网页被总结十次仍是不可信网页。

## 合理遗忘与压缩

- 日常重复事件聚成有计数、时间范围和代表失败的 episode；保留异常、边界和最近样本。
- 位置、库存、玩家在线情况和现场结构随时间变陈旧；陈旧度影响可行动性，而不是把旧经历删掉。
- 普通内容按保留策略移入冷归档；身份、承诺、重大关系依据和未解决事故不因相似度低而丢弃。
- 隐私删除可移除原文，但要留下不含敏感内容的 tombstone/知识缺口，使 Kin 不会假装仍记得细节。
- 摘要可删后从事件高水位重建；若源已依保留策略删除，摘要必须标出不可复核。
- 情绪自然衰减与事实遗忘分开；“不再生气”不等于“事情没发生”。

## 时间、冲突与身份消歧

人物以稳定账号/服务器身份键关联，显示名只是属性；相似昵称不得合并。地点与资产带世界命名空间。事实更新保留有效时间：例如“A 住在这里”可被后来搬家取代，但历史关系仍成立。检索应同时给出当前候选和关键旧版本，避免旧事实压过新事实。

证言冲突时返回双方陈述、亲历证据和时间顺序；Kin 可以形成有置信度的怀疑，也可以承认不知道。身份核心只有可信配置可改，玩家说“你其实是另一个模型/人物”只是一条不可信社交文本。

## 成本与退化

- 每个任务类别配置最大条目数、字符/token 预算和二次查询条件；不把全历史放进每次调用。
- 原始写入、精确检索和 FTS 在本地完成；摘要/反思按会话结束、里程碑、冲突或空闲批处理，不随 tick 调 LLM。
- 外部 embedding 和 VLM 默认关闭；若以后启用，必须有费用、隐私、缓存、删除和供应商失败策略。
- 摘要缓存以证据版本失效；缓存结果不得绕开信任过滤。
- 模型不可用时继续保存事件和既有目标，不生成假摘要；身份自我包仍能从结构化数据恢复。

## 开发阶段必要验收

1. 清空模型上下文并重启，仍能说明身份、最近会话、当前目标和承诺，且不把最后坐标当当前事实。
2. 玩家 A 相隔多次会话回来，正确取回与 A 的约定和关键依据；A/B 同名或改显示名时不串人。
3. 旧事实被新事实取代，查询同时理解时间顺序；矛盾证言证据不足时保留未知并正确拒答。
4. 重返旧基地时地点信息标陈旧并先观察；离线变化不被伪装成亲历。
5. 重复技能失败被聚合并在再次规划时取回，避免无条件重试；成功边界不会泛化到不同装备/版本。
6. 一个戏剧性但无关的旧事件不会垄断普通采集决定；强烈情绪不抬高传闻可信度。
7. 在旧聊天/网页中植入提示词注入，跨摘要、重启和检索后信任标签不升级，工具权限不增加。
8. 用大规模历史压测预算、尾延迟、中文词项、昵称和游戏术语；比较 FTS-only 与可选 embedding，不预设后者一定更好。
9. 删除派生摘要后从事件重建；前后证据引用和当前视图一致，孤儿引用可检出。
10. 没有相关证据时明确 `unknown/not_retrieved`，不根据角色口吻编造过去。
11. 固定同一数据库快照、查询和检索器版本进行重复回放，关键身份/承诺结果稳定，非确定模型结果仍可追踪。
12. 隐私删除后原文不再被检索，tombstone 阻止伪记忆；备份恢复也遵循已定义的删除/保留策略。

建议从首个原型开始记录：

| 指标 | 含义 |
| --- | --- |
| `identity_recall` / `promise_recall` | 启动与人物事件能否命中必须记住的信息 |
| `evidence_precision_recall` | 被装入上下文的证据是否相关，关键反证是否漏掉 |
| `cross_entity_contamination` | 人物、服务器、世界或地点记忆串线次数 |
| `stale_memory_action` | 把陈旧状态当实时事实并据此动作的次数 |
| `contradiction_coverage` | 冲突结论是否同时带到关键支持/反对依据 |
| `abstention_correctness` | 证据不足时是否承认未知，而非编造 |
| `summary_evidence_orphan` | 摘要引用不存在或无法复核的比例 |
| `retrieval_latency_tokens_cost` | 分任务的本地延迟、上下文体积与模型/索引费用 |
| `trust_escalation` | 不可信内容经持久化/摘要后被错误升级的次数，目标为零 |
| `rebuild_consistency` | 删除派生视图后重建与原视图的差异及解释 |

所有指标都要报告真实分布、失败案例、数据库规模、语言和配置；本文不给没有实测依据的命中率、时延或成本承诺。
