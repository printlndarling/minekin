# 自主学习：从经历到可复用技能

Kin 入世前已有[原版世界书](world-guide.md)，但它不是一份永远正确的答案库。Kin 可以主动查公开资料、在世界里试做、复盘结果并改进下次做法。学习不等于一次成功后生成一条永远执行的脚本；它需要知道方法在哪个版本、环境和资源条件下成立，哪些判断只是猜测。

## 学到的东西放在哪里

| 层 | 例子 | 信任和复用方式 |
| --- | --- | --- |
| 亲历事件 | “今天试建的塔几乎没有怪，施工时我看见平台上有火把” | 带时间、观察来源和结果保存；事件不能自动证明失败原因 |
| 归纳信念 | “照明可能是低产原因，另一个可能是附近洞穴占刷怪上限” | 关联支持/反证事件，保持竞争假设，遇新证据可修订 |
| 外部知识 | 某 Java 版本的刷怪机制、教程条件及来源 | 先是公开资料的主张；核对版本后仍要验证本服务器条件 |
| 候选方法 | 建塔步骤、材料和选址检查表，附未知条件与试验计划 | 可以用于下一次规划，但标注未掌握，允许现场修改或放弃 |
| 已验证技能 | 多次适用条件下能完成的“选址→建造→测试→排错”程序 | 按需检索、检查前提后组合本地技能；失败再降级或修订 |

社会学习和施工学习不同。Kin 可以总结“Steve 多次违背借物约定，今后先核对归还条件”，但这是可反驳的关系信念和行动倾向，不应编译成“碰到 Steve 就追杀”的固定技能。情绪会改变学习关注的事情，例如资源失窃后更愿意检查权属与箱子安全；强烈感受不能替代证据。

角色的[开局领域知识画像](knowledge-profile.md)与后天实战技能分开：一个方法被理解或检索到，不代表 Kin 已经做成。水桶落地、高压战斗等高阶动作要检查角色亲历、装备和实时条件；尝试的结果才更新个人熟练范围，见[实战技能](ability.md)。

## 自主学习闭环

1. **识别缺口**：自己任务失败、遇见新物品、模型知识与当前游戏版本不符，或朋友提出它不会做的目标。先看世界书和已有技能；必要时建立受限的 `research` 目标。
2. **形成方案**：区分公开机制、他人的说法、亲眼观察与推测。写下适用 Java 版本、服务器公开条件、材料、前置技能、预计代价、失败迹象和可取消条件。
3. **安全试做**：通过本地行为层和合法客户端输入尝试；紧急反射可抢占。记录目标、开始条件、实际行动、观察到的结果与中断，不把教程写的预期当作实际结果。
4. **归因与修订**：成功和失败都复盘，比较竞争解释；有足够证据才修订方法。未知原因留为未知，不把一次偶然成功升级为“精通”。
5. **按需复用**：下次目标出现时，只加载相关技能的索引与必要步骤，先验证版本、环境、装备和个人能力；条件不成立则研究、改造、退回候选方法或拒绝承诺。

以刷怪塔为例，网页教程只是候选方案。Kin 可以与玩家商量材料和选址，建好后观察怪物和经验产出，再检查照明、可观察的周边环境和公开服务器规则。若产量不足，它记录“低产”和几种可能原因，再试改造；不会在数据不足时声称已经学会稳定建塔。验证过的排错步骤比一张完整施工图更值得沉淀。

## 技能表示与升级门槛

重复操作不应只留在日志里。初期允许 Kin 主动提炼可调用的**组合技能**：从亲历中识别相似任务，提出适用条件、步骤、所用基础客户端能力、可观察完成信号、失败时的回退；下次遇到同类任务时按需加载并实际调用，再依据结果精炼或拆分。它可以自行创建或修订说明型条目和受约束的结构化流程，不要求自己写一个新的 Fabric 战斗模组。一个技能至少包含 `name`、触发目标、来源事件/资料、适用版本、前提、步骤/子技能、可观察完成条件、失败与回退、验证历史和修订记录。目录只暴露名称、用途和适用范围；规划时再读取步骤，借鉴 [Hermes Agent 技能文档](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills)中的按需展开和自主创建技能思路；Minekin 的动作步骤需通过自己的能力清单与客户端适配器验证。这是借鉴设计，不表示 Hermes 的通用技能文件可直接操控 Minecraft。

例子：Kin 反复为项目备工具时，可以沉淀“确认现有背包与工具 → 找到缺少的木/石 → 合法采集或使用储备 → 按所选版本配方打开 GUI 合成 → 检查库存 → 失败时回看哪一步未成功”的技能。下次为修房子备工具，Kin 可按条件复用而不必每次从头构思；已有工具便跳过制作，配方或 GUI 变化便暂停并修订。技能表达的是 Kin 自己总结、选择与调用的方法，不是强制所有 Kin 在每个出生世界按相同顺序行动。

候选方法升级为稳定技能的条件由任务类型决定：至少有可回放的成功与失败或边界案例、条件检查能挡住已知错误、完成能从游戏观察核验；跨版本、跨服务器的适用性未验证时必须缩小声明范围。重复失败、版本升级、资源缺失或新的可靠反证会让技能进入待复查状态，旧版本保留供解释与恢复。技能可以组合现有移动、放置和物品管理能力，但经验条目不得绕过感知过滤、反射抢占和合法客户端操作。

不把外部网页的代码/命令自动执行，也不让 Kin 因查到教程就修改本机模组、服务器规则或其他玩家物品。首版学习目标是 **自主发现问题、将重复经验封装为实际可调用的组合技能、复用后精炼方法**；已有动作能力可以结构化编排并由本地控制器执行。若现有动作能力不会盾牌防御或定位施工方块，封装流程不能凭文字补出底层能力；是否允许自动生成新的客户端动作代码，需要原型中独立验证兼容性、动作边界和错误恢复后再定。

## 衡量与待讨论

- 在相似任务的第二次尝试中，是否正确调用旧经验并减少同类错误；每次复用要能追溯至事件、版本与前提。
- 能否自主提出、建立、调用并修改组合技能；区分“写出文档”“成功调用身体动作”和“实际任务完成”，记录调用次数、前提拒绝与复用后的改进。
- 在错误教程、版本升级、偶然成功或反例出现时，是否降级或修订技能，而非重复自信的失败步骤。
- 失败报告能否区分“动作未执行”“方法不适用”“外部资料错误”“目标已取消”，并据此改变下一次计划。
- 对社交经历能否保留不确定性、承认误判和修改关系信念，而非自动产生伤害性的固定套路。

未来可试更丰富的技能库、自动组合甚至新客户端动作实现，但前提是单 Kin 原版生存的自主学习闭环先在回放场景成立。
