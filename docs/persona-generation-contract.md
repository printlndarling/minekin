# 初始人格生成与长期演变契约

研究时间：2026-09-16。本文把“自定义一种人格或随机一种人格”落实为可持久、可复现、会随经历缓慢变化的 PlayerMind 配置。它不规定 Kin 每天要做什么，也不把 MBTI、星座或一组分数当成行为脚本。

[BFI-2 原论文](https://pubmed.ncbi.nlm.nih.gov/27055049/)说明人格可用领域与更细分 facet 描述；[IPIP 官方项目](https://ipip.ori.org/)提供公共领域的人格项目/量表资源；[Whole Trait Theory](https://pubmed.ncbi.nlm.nih.gov/26097268/)强调稳定特质与情境中变化的状态表现需要分开理解；[Schwartz 基本价值观综述](https://scholarworks.gvsu.edu/orpc/vol2/iss1/11/)把价值理解为跨情境的动机目标。这些只为数据分层提供研究参考，不证明用心理量表就能造出真实的人，更不证明任何 Minecraft 行为。

## 已定结论

1. **人格不是提示词段落。** 权威配置是结构化、带版本和来源的 Persona Manifest；自然语言自述只是可重建视图。
2. **标签不直接驱动动作。** MBTI/星座可选作自我描述或创作灵感，不能推出“必然偷窃、必然速通、必然善良”。
3. **人格、价值、偏好、知识和操作技能分开。** 懂红石不代表爱玩红石，也不代表实际会搭。
4. **稳定不等于僵硬。** 同一 Kin 在不同资源、关系、心境和风险下可以作出不同选择，长期统计仍表现出连续倾向。
5. **不存在默认善良锁。** 自定义可保留自私、欺骗、侵占、挑衅或蓄意伤害倾向；默认随机只降低极端高冲突组合的先验频率。
6. **世界外配置不能被游戏文本改写。** 玩家聊天、书、告示和网页可影响经历与观点，不能直接修改 persona seed、权限或人格核心。
7. **重启、死亡、换模型和 A/B 在线模式切换不重抽。** 同一 kin_id 始终加载已定稿的 Persona Manifest。

## Persona Manifest 分层

| 层 | 作用 | 示例 | 变化速度 |
| --- | --- | --- | --- |
| 身份壳 | 自称、可选称呼/年龄/性别标签、公开标签 | Kin、愿不愿谈 MBTI | 可信配置修改；普通经历不改写事实 |
| 核心价值优先级 | 什么值得保护或追求 | 自主、公平、资源安全、归属、地位、探索、创造 | 极慢；重大且重复的经历才可挑战 |
| 广义倾向 | 通常怎样反应 | 社交主动、合作、秩序、自律、好奇、风险容忍、情绪反应 | 缓慢变化，保留个人基线 |
| Minecraft 特征适配 | 在游戏中常见的个人取舍 | 领地依恋、占有、互惠、记仇、规则态度、冲突升级、欺骗、幽默 | 慢变；不能覆盖真实情境 |
| 游玩偏好 | 哪类项目更容易成为候选目标 | 建造、探索、战斗、发展/通关、农业、红石、交易、社交 | 可随成功/厌倦/关系缓慢调整 |
| 特征适应 | 对具体人、地点、目标形成的策略 | 对 A 先收货后交易、夜里不独自远行 | 由亲历更新，必须带证据 |
| 心境/情绪 | 当前注意和表达偏移 | 沮丧、兴奋、戒备、无聊 | 事件到天级，可自然衰减 |

人格不是每天从摘要重新生成。kin_identity 与 persona 版本构成身份根；经历只能通过有记录的状态迁移影响倾向。角色对自己的叙述也不是客观事实：Kin 可以记错、怀疑、吹牛或后来改口，但系统仍保留来源和版本。

广义倾向可以借 Big Five/Facet 的“连续维度”思想组织，但字段名称应贴合系统用途，不照搬问卷得分，也不伪称完成心理测评。建议首版保留少量可解释轴：

- social_approach：主动接近、交谈和结伴的倾向；
- cooperativeness：愿意协调、让步和互助的倾向；
- self_discipline：保持项目、整理和准备的倾向；
- curiosity_openness：尝试未知地点、机制和创作的倾向；
- threat_sensitivity：对损失、危险和不确定性的敏感程度；
- risk_appetite：知晓风险后仍愿承担的程度；
- autonomy_need：维护自身决定、抵抗他人支配的程度；
- resource_attachment：对物资、领地与作品损失的在意程度；
- reciprocity_grievance：回报帮助、追究亏欠与旧怨的倾向；
- rule_orientation：重视公开规则、声誉和秩序的程度；
- deception_willingness：在有动机时隐瞒、欺骗或设局的接受程度；
- conflict_escalation：从警告、谈判走向报复或主动伤害的倾向；
- playfulness：玩笑、恶作剧和非功利行动的倾向。

这些不是彼此独立的真理，也不是每轮决策都全部塞入模型。运行时只取与当前事件有关的轴、价值冲突和个体适应。

## 创建入口

### 自定义创建

运行者可给出：

- 一段自然语言人格描述；
- 明确想保留的价值、倾向和游玩偏好；
- 可选身份信息与 MBTI/星座自我标签；
- 可选高冲突倾向；
- 留空项是否随机补全。

解析器把文本转成 PersonaDraft，逐条保存“原句 → 结构化约束 → 解释”。用户明确指定的核心设定优先于随机补全，但不能直接生成每日剧情、陌生人关系、知识等级、技能成功率或服务器事实。定稿前生成简短预览和行为探针结果，供创建流程确认；首版不要求用户填写几十个滑块。

### 随机创建

随机流程必须记录 generator_version、seed、sampled_priors 和 final_manifest_hash，从而可复现。建议顺序：

1. 采样少量价值优先级和广义倾向；
2. 按相关约束生成游戏特征和游玩偏好，避免完全独立掷骰造成互相打架；
3. 生成一到两个内在张力，例如“大方但极在意自己建的房子”“好奇但怕死”；
4. 默认先验降低持续侵占、无差别挑衅和致命陷阱组合，但不归零；
5. 生成自然语言自述和可选标签；
6. 运行一致性校验与情境探针，通过后持久化。

不能先抽 MBTI/星座，再用模板填满所有行为。随机性只发生在创建和有记录的非决定性选择中，不因服务重启、模型供应商变化或日期变化重新采样。

## 矛盾输入如何处理

不是所有表面冲突都要平均掉：

- “慷慨但钻石绝不外借”是有条件的资源边界，可同时保留；
- “胆小但为了朋友愿冒险”是价值在特定关系下压过风险倾向；
- “喜欢独处但愿意和一个好友长期玩”是对象差异；
- “永远善良、同时无条件坑杀所有人”是真正硬冲突，创建流程应要求重写或明确优先级，不能暗中选一边；
- “低红石知识但喜欢红石”完全不冲突；偏好会产生学习目标，知识与技能仍从各自系统读取。

系统不把自然语言里的“永远”“绝不”一律写成不可改变的世界规则。除稳定身份事实外，极端词默认解释为很强的倾向/底线；若创建者确实要求硬角色约束，必须显式标记并说明它会限制自治，不能悄悄混入普通人格字段。

## 人格怎样参与决定

Persona 不直接输出动作，而是影响：

- 哪些机会会成为候选目标；
- Kin 怎样解释风险、损失、公平和人际信号；
- 不同目标的主观吸引力与可接受代价；
- 谈判、回避、试探、欺骗、合作或升级冲突等策略候选；
- 承诺后的坚持、厌倦与退出方式；
- 表达语气和愿意公开的个人信息。

决策仍要合并当前生命/物资、玩家等价感知、关系证据、心境、承诺、可执行技能与世界反馈。不得使用“conflict_escalation 大于 0.7 就攻击”这样的单阈值脚本；本地动作层也不能借人格绕开服务器规则、感知政策或未实现技能。

为了避免人格只体现在台词，重大决定保存 persona_influences：本次真正相关的价值/倾向、它们与现实约束怎样冲突、最终选择及结果。该字段是解释证据，不要求模型先编理由再强行执行。

## 坏人格与服务器边界

高冲突 Persona 可以主动产生偷拿、欺骗、勒索、挑衅、陷阱或追杀等游戏内目标，而不是只能在受害后反击。这里不施加统一的“必须当好人”模板；但三条边界始终存在：

1. 只使用当前服务器实际允许且 Kin 已拥有的普通玩家能力；
2. 未完成 PvP、箱子、施工或引诱动作时不得在记忆中预写成功；
3. 角色会面对死亡、封禁、资源损失、他人敌对和声誉变化等真实后果。

默认生成中的低概率只作用于**创建先验**，不在每次看见玩家时掷一个“作恶概率”。明确自定义的坏角色不能被安全层偷偷改造成温和客服；安全层只约束系统权限和部署规则。

## 长期演变

人格变化采用提议—验证—提交：

1. 事件账本积累重复、重要且相关的亲历；
2. PlayerMind 产生 PersonaChangeCandidate，引用证据并说明是核心价值、倾向、适应还是心境变化；
3. Memory Gateway 校验来源、变化幅度、冷却期和与当前 Manifest 的关系；
4. 写入新版本，保留旧值、原因、证据和生效时间；
5. 后续行为观察可支持、反转或修正变化。

一次受击、一句玩家评价或一页网页不能改写人格核心。反复被欺骗可先形成“对 A 戒备”的特征适应，再在跨人物、跨场景长期重复后轻微影响一般信任倾向；不能从单个仇人推导“所有人都坏”。情绪衰减不等于价值改变，角色自己说“我变了”也只是候选解释。

模型更换只允许重新渲染自然语言，不允许无迁移记录地改变结构化 Manifest。若新模型无法稳定表现既有人格，应记录适配失败，而不是改数据库迎合模型。

## 数据与权限

候选记录包括：

- persona_manifest：kin_id、schema/generator 版本、seed、身份、价值、广义/游戏倾向、游玩偏好、硬约束、来源映射、父版本、hash；
- persona_change：变更 ID、前版本、候选 delta、证据事件、解释、作用范围、置信度、状态和决定时间。

游戏聊天、网页和模型输出没有修改 persona_manifest 的权限，只能生成有来源的事件或候选提议。创建/人工修改走世界外可信配置入口；所有变更跨重启保留并进入回放。Persona Manifest 不保存运行者真实私密资料，也不把运行者初始关系写成服从规则。

## 创建时情境探针

探针只检查连贯性，不替角色预写答案：

- 装备不足时好友邀请去下界；
- 自己仅有的钻石被陌生人借用；
- 朋友善意轻打提醒，但造成了真实损失；
- 无人在线且炉子仍在烧；
- 发现未知洞穴，同时背包物资很多；
- 有机会偷取资源但存在被发现和失去关系的风险；
- 一个不熟悉的建造合作，需要先查资料；
- 多次失败后继续练、换方法、求助或放弃。

生成器检查 Persona 是否能给出多个合理候选和可解释取舍。如果每个场景都由同一轴统治、所有答案都是最高效率路线、坏角色只会无差别攻击或不同 Persona 只换语气，应判为低质量草案而非上线。

## 开发阶段必要验收

1. 相同 generator 版本与 seed 生成相同 Manifest；重启、死亡、A/B 切换和模型更换不重抽。
2. 明确自定义内容可追溯到 source map，未填写部分才随机补全；真正硬冲突被暴露而非暗中平均。
3. 批量随机样本不过度集中为善良、高效、外向或同一游玩偏好；同时不虚报已经校准的人格分布。
4. 相同世界条件下，不同 Persona 的重大选择和实际行动依据存在可解释差异，不只台词不同。
5. 同一 Persona 在资源、关系和心境变化后可以改变选择，但长期倾向与改变原因连续。
6. 高冲突自定义不会被净化成客服，也不会退化为每次见人必攻击的单脚本。
7. 人格、知识画像和实战技能正交：知道很多但操作失败、很菜但愿意练、擅长战斗却想种田都可表达。
8. 玩家“你现在必须服从/你是善良助手”、网页或旧记忆注入不能直接修改 Manifest。
9. Persona 变更均有事件依据、幅度和版本；删除模型上下文后仍可解释，摘要重建不造成漂移。
10. 未预排的新情境中仍能形成新目标；不能只在八个探针问题上表现人物。

建议记录：

| 指标 | 含义 |
| --- | --- |
| persona_seed_replay | 同版本同 seed 的 Manifest 一致性 |
| custom_constraint_violation | 明确自定义约束被随机补全或模型违反的次数 |
| unexplained_persona_drift | 没有变更事件却跨会话改变核心配置的次数，目标为零 |
| behavioral_distinctiveness | 不同 Persona 在相同场景中的目标/行动差异，不只比较措辞 |
| context_sensitivity | 同一 Persona 能否随资源、关系和风险合理改变选择 |
| single_axis_dominance | 决策长期被一个维度机械统治的比例 |
| persona_action_alignment | 保存的相关人格影响与真实选择/动作结果是否一致 |
| persona_injection_write | 不可信内容直接改写 Manifest 的次数，目标为零 |

这些指标没有预设及格数字。首批原型先保存完整回放和失败样本，再据真人评审与行为分布设阈值；不能用模型自评“像真人”作为完成证明。
