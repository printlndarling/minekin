# 合成结果存放的窗口槽位

基线 `368dd19`。`craft_take_result` 的备用存放分支此前只按玩家 2×2 窗口映射槽号。工作台窗口中，背包快捷栏槽 0 被误点为窗口槽 32，而正确槽号为 37；新工作台回归在修前失败（实际 32 / 期望 37）。

现在映射依据当前玩家可见的窗口类型：玩家背包快捷栏 32..40、主区 5..31；工作台快捷栏 37..45、主区 10..36。工作台映射由本地受管 1.20.1 的 Yarn 映射 jar 中 `net.minecraft.screen.CraftingScreenHandler` 构造器字节码核对：结果槽、九个输入槽、二十七个背包槽、九个快捷栏槽按次序加入。玩家窗口在 Bridge 的实际读数为无类型名且 sync_id=0；保留既有测试别名 PlayerScreen。

配方点击前拒绝未知容器布局。配方填充、结果槽点击、备用存放绑定同一窗口类型及 sync_id；窗口关闭或切换且产物尚未确认时按 `SCREEN_NOT_CONFIRMED` 停止，不把存放点击送往另一容器。库存已经确认产物的读数仍可确认，不因窗口变化抹掉实际结果。

验证：关联技能、计划、自主循环 **258 passed**。其后增加填充期间类型变化检查，最终合成定向 **22 passed**；类型、ruff 与格式检查通过。覆盖工作台和玩家窗口、快捷栏/主区边界、已占用槽跳过、窗口切换/关闭、未知容器拒绝及切换后产物已确认的正对照。

这是代码与受控观察测试，未启动 Minecraft，未连接远程服，不是当前构建真实模型 3×3 合成证明。下一步仍是资源与端点窗口内的该活体闭环，以及导航、生存、恢复的当前构建验证；完整项目保持进行中。
