## 1. 缺陷陈述

`test-orchestrator/runner/domain.sh:2617`（起点字节）等待「服务端记下这场会话被结束」的 grep，行续符退化成了字面量 ` \n `：

```

```

bash 把 `\n` 当一个词展开成裸 `n`，词表实测 `[Kin (lost connection|left the game)] [n] [server.log]`（M 材料 `.tmp/m-r65-kick-grep-shape2.log`，本树复现同形，见 §4）。于是 `n` 成了 grep 的第二个文件操作数：

- **假绿**：工作目录存在内容为 `Kin lost connection` 的文件 `n`、`server.log` 没写那句 ⇒ `rc=0` ⇒ `kicked=1` ⇒ 打印 `domain: the server ended the session while the client kept running`。M 量到 `false_green_test_server_says_nothing_n_says_kick=0`。
- **错误码被吞**：`n` 不存在且无匹配 ⇒ `rc=2`（不是 1），`2>/dev/null` 把具名错误一并吞掉（M 量到 `shipped_shape_with_n_absent=2`）。

`kicked` 只在 stderr 报一行、无别的消费方 ⇒ 伤害是**读数面**的假绿，不是流程卡死。
