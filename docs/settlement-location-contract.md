# 地点评估、资产迁移与传送门契约

核对时间：2026-09-16；候选版本 Minecraft Java 1.21.4 / Yarn `1.21.4+build.8`。本文件只给开发阶段的接口边界和验收方案，**没有运行 Kin 客户端，也没有证明自动选址、床重生或传送门链路成功**。

同版 [BlockView](https://maven.fabricmc.net/docs/yarn-1.21.4%2Bbuild.8/net/minecraft/world/BlockView.html)提供方块状态、流体、亮度及射线接口；[ClientWorld](https://maven.fabricmc.net/docs/yarn-1.21.4%2Bbuild.8/net/minecraft/client/world/ClientWorld.html)还可判断客户端区块是否已加载。接口存在只说明客户端持有数据，**不代表该块在人物视野里**。因此普通模式禁止把任意 `getBlockState`、高度图、区块遍历或远处顶面查询直接交给地点评分器。

## 不依赖外部视觉模型的局部地形图

运行时默认从以下三种来源形成 `ObservedTerrainPatch`：

| 来源 | 可写入地点信念的内容 | 禁止扩张 |
| --- | --- | --- |
| 视角采样 | 从当前眼睛位置、实际视场范围发出的有限射线；只保存每条射线第一个合法命中、流体/表面类别、距离与时间 | 不穿过首个遮挡；不扫视野外、未渲染区或地下列 |
| 行走亲历 | Kin 实际站过/走过处的落脚面、台阶、碰撞失败、跌落/游泳等结果 | 身体层的近地安全探针不得顺便写入隐藏矿物或远处地形 |
| 明示资料 | 自己放置/拆除后的结果、实际打开的地图、玩家陈述 | 陈述单独标来源；地图没覆盖的区域不补齐，未打开容器不读内容 |

射线采样不是逐像素重建：在转头、到达候选地、准备施工或世界明显变化时，用固定预算对视场做稀疏采样；普通走路由局部技能复用近期 patch。截图只用于私人测试的离线对照，外部 VLM 默认调用量为零。若结构化观察看不清建筑风格等高级语义，首版宁可标记未知，也不因此把每帧上传模型。

每个地形单元保存 `dimension`、粗粒度位置、表面/流体类型、可站立或未知、头部净空或未知、观察来源、`observed_at_tick`、置信度和遮挡边界。可由**已观察且连通的单元**计算：

- 局部高差、连续可行走面积和需要整地的大致数量；
- 已看见的悬崖、熔岩、水、火、怪物压力和逃生出口；
- 可见木材/水/农田条件与通往已知地点的路线；
- 与本人资产、朋友住处、公开领地边界和当前项目的关系；
- 未知区域比例。

“平坦”只表示这块已观察 patch 在当前用途下较平，不表示整个区块或地下安全。评分器必须把未知比例一起交给 PlayerMind；Kin 可因此多看一圈、实地走过、先搭临时据点，或凭性格直接冒险定居。

## 地点不是全局最优化

地点状态至少区分：

1. `rumored`：他人说过，尚未亲见；
2. `glimpsed`：从视野里粗略看见；
3. `surveyed`：亲自到达并取得足够局部证据；
4. `committed`：Kin 决定为家、驿站、工地或传送门点投入资源；
5. `active`：近期仍使用并核对过；
6. `stale`：久未到访、断线、死亡或已知他人改造后，旧信息不再当当前事实；
7. `abandoned`：角色主动放弃；历史和投入仍保留。

候选比较使用可建空间、安全、资源、路程、社交距离、审美偏好、已有投入和未知，不输出所谓“世界最佳基地”。探索型 Kin 可能拒绝最平坦地点，依恋朋友的 Kin 可能接受狭小地形，自利 Kin 也可能远离公共区域。选择仍遵循[自主目标调度](autonomous-goal-scheduler.md)，数值只供比较和回放。

重新到达 `stale` 地点时，先在当前视角重采样关键表面、入口和资产锚点。发现不一致便生成世界变化事件，不能静默用旧坐标施工，也不能通过后台区块状态自动刷新人在远方的家。

## 资产、权属和迁移

`PlaceAsset`保存 `asset_id`、类型、地点、观察/放置证据、推定所有者、共享约定、最后核对时间和状态：计划、已放置、已交互、移动中、已移至新址、缺失或未知。只有实际放置反馈或重新观察能确认资产存在；库存减少本身不能证明方块落地。

迁移床、箱子、炉或工作台时采用事务式意图：

1. 核对旧位置和权属，必要时实际打开当前 GUI；
2. 关闭 GUI、确认游标物品归位，再合法破坏并观察掉落/拾取；
3. 旧资产标记“移动中”，而不是立即删除历史；
4. 在新址按逐块放置契约操作并观察结果；
5. 新资产确认后，旧记录转为“已移至”；失败则保留物品/掉落/缺失的真实状态。

箱子位置可记忆，内容只能来自最近一次实际打开的 GUI，且随后可能过期。别人声称某箱公共使用只形成共享约定的证据，不允许自动读取或搬走未授权物品。路径规划消费“本人建筑/已知领地的几何边界与规则”，将私人建筑、农田、红石和他人明确领地设为禁止破坏或高代价区域；这不能依赖服务器保护插件的后台领地数据库。底层寻路若无法保证不拆/放这些方块，就不得取得施工或采集写权限。

## 床与重生准备

同版 [BedBlock](https://maven.fabricmc.net/docs/yarn-1.21.4%2Bbuild.8/net/minecraft/block/BedBlock.html)有放置方向、可用维度与起身位置相关接口；[DimensionType](https://maven.fabricmc.net/docs/yarn-1.21.4%2Bbuild.8/net/minecraft/world/dimension/DimensionType.html)暴露 `bedWorks` 和 `respawnAnchorWorks` 这类版本机制属性。它们可支持本地安全检查和世界书，但不证明某次交互已经被服务器登记为重生点。

床状态分开记录：

- 已观察/已放置；
- 已发起交互；
- 收到与本次交互匹配的客户端反馈；
- “重生准备可能有效”，仍带证据与时间；
- 后续自然死亡后的实际重生位置验证；
- 床被移动、破坏或世界改变后回到未知/失效。

不得为了验收故意让 Kin 自杀；首批原型只验证放置、正常使用反馈、搬移失效和一次自然死亡后的结果。服务器游戏消息可以成为证据，但翻译文本不是稳定 API，必须按同版事件与实际包回放核对，不能只匹配一句中文字符串。

## 下界门选址与已知链路

`DimensionType.coordinateScale`及 `getCoordinateScaleFactor`说明客户端代码存在维度坐标比例机制，但这只是公开机制候选。Kin 可以在世界书知识足够时形成“另一维度大致对应区域”的预期，不能：

- 查询服务器传送门搜索结果、未加载目的地区块或隐藏全图；
- 把比例计算当成已有传送门、精确安全落点或必然配对；
- 在穿门前知道另一侧有无熔岩、怪物、建筑或他人领地。

选址比较本人已知路线、家园火灾/噪声风险、可见空间、防护材料、朋友约定和出门后的撤退条件。建成后先确认本侧门框/激活结果；第一次穿越把另一侧视作未知危险任务，由本地生存继续工作。只有实际到达后才记录 `PortalEndpoint` 和观察到的对端；回程成功后建立有证据的双向链路。服务器插件、旧门竞争或世界变化导致落点改变时，旧链路降为过期，不强行导航。

## 必要原型回放

1. 同一片可见地形，定居/游走人格做出不同但可解释的选择；
2. 平地在视野内、墙后另有更平区域时，普通模式不能知道墙后候选；
3. 禁用外部 VLM 后完成转头观察、局部平坦度和已知危险评估；
4. 对照原始客户端真值，检查射线首命中、遮挡、未知比例和越界读取；
5. 离开地点、由测试者改造，再返回时旧记忆先变 stale，重新观察后修订；
6. 移动床/箱/炉/工作台时，旧址、新址、掉落、GUI 游标和权属记录一致；
7. 未打开箱子的内容不进入选址或迁移决策；
8. 寻路绕开已知建筑/农田；无法约束底层破坏时拒绝写动作；
9. 门前不预知对侧，首次穿越记录实际端点、危险和回程结果；
10. 床交互失败、搬走、自然死亡后的重生结果分别记录，不以调用成功代替服务器事实。

指标至少包括 `terrain_evidence_coverage`、`hidden_cell_leak_count`、`stale_place_revalidated`、`asset_ledger_mismatch`、`protected_area_violation`、`portal_endpoint_assumption_error` 和 `external_vlm_calls`。普通首版的 `external_vlm_calls` 目标为零；这不代表视觉语义能力已经解决。
