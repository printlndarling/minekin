# 成本、回放与研究→开发的验收边界

截至 2026-09-16 尚无 Kin 的运行测量：本页的预算和量化要求是**可测试设计**，不是声称已有毫秒级救援、全自动通关、零注入泄漏或稳定费用。单 Kin 本地 SQLite 事件账本（见[数据契约](mind-data-contract.md)）与有限后台模型调用是首版候选；实际型号、实时单价、TPS/FPS、显存/内存/电耗待具体环境测量后锁定。

## 可审计跨层链路

每次行动记录 `episode_id`、`client_tick`、单调时钟时间、实际 Java/客户端/Fabric/服务端版本、`persona_id`、`goal_id/intent_version`、观察来源/有效期、感知模式和例外开关、决策层/动作原语/抢占、服务器同步反馈、是否从自己的客户端可观察完成。异步研究有 `research_id`、查询权限/目标、资料来源、有效期、取消、候选技能版本；模型调用只存模型**成本分类**、调用时长、输入/输出 token 数与失败类别，真实模型名称/密钥仅在管理侧访问控制记录，不进入 Kin 社交上下文。基于 [OpenTelemetry trace/span 官方概念](https://opentelemetry.io/docs/concepts/signals/traces/)可用操作 span、时间戳事件与 span link 关联客户端动作和迟到的后台查询，但不需要首版强制部署整套远端追踪平台。

测试服可另有服务器真值和截图用于离线比较感知，但与线上 PlayerMind 的事件库/日志访问权限彻底隔离，避免回放数据绕过“玩家等价”。日志中的其他玩家账号、聊天和房屋位置属需要保护的信息：默认只保留最少审计字段，敏感正文缩短保留期/脱敏，原始截图和服务端真值仅在受控测试中使用；公开 Demo 必须得到参与者同意和脱敏。运行中数据库依 [SQLite 官方 WAL](https://www.sqlite.org/wal.html)/[在线备份接口](https://www.sqlite.org/backup.html)安排一致性备份，不直接拷写入中的单个 db 当完整快照。恢复验证死后/重启后同一角色记忆，不等于黑盒 LLM 原样重放必然确定：回放应冻结输入、原始响应和随机种子，分别报录制模式与重新推理模式。

## 延迟、资源与账单

记 `N_m` 为每日某类型模型请求数、`I_m/O_m` 为输入/输出 token、`P_m^in/P_m^out` 为当前官方单价、`N_w` 为搜索次数、`P_w` 为对应计费，再加服务器、独立账号、机器电耗和可能的视觉请求。日计费估计 `Σ_m(N_m × (I_m × P_m^in + O_m × P_m^out)) + N_w × P_w + 固定资源成本`，实际还需注意价格计量单位、缓存折扣、重试、货币/税和失败调用计费。**不写“每小时 x 元”未经实测结论**；当前价格只可引用当日供应商官方页后锁预算版本。

配置每游戏日/自然日的模型 token、搜索数、**默认 0 次外部视觉调用**（可选开启后才配置视觉帧数）、总费用阈值及运行者告警；Dashboard Live View 是给人类看的独立媒体流，不计为 VLM 调用，也不得自动回流模型或人物记忆；高层采用状态变化触发与低频心智检查而非 tick 级调用，B 模式没人时并不强制持续推理。到额/断网/模型超时：禁止新高风险计划和新的公开研究调用，本地反射与已验证保守动作仍可运行；超期的高层响应因 `intent_version` 不匹配而丢弃，不能覆盖紧急抢占。反射控制器的 tick 占用、下落触发到首次合法输入、FPS/TPS/RTT、P50/P95/P99 延迟应多次实测；Minecraft 20 TPS 理论逻辑 tick 约 50ms，但**单个事件/网络/图形帧不能据此保证 50ms 完成**。记录空载、下落、水桶不可用、同步慢和突然受击等不同条件，不宣布 100% 水桶成功。

## 进入开发阶段的文档门槛与原型通过条件

“可以开始正式编码”不是“Kin 已具备能力”。研究项在[台账](research-tracker.md)须有来源支持的候选方案、明确的替代/失败回退及**阶段 0–后续原型必须实测的未定事项**；环境和许可证存在阻断时不能放行。设计文档互相一致，归属/隐蔽真值/运行者权限和人物自主性边界已冻结；重大项目走向有待用户决定时单独列出，先做完其他独立调研。

| 开发阶段证据门槛 | 必测回放及报告 | 若失败 |
| --- | --- | --- |
| 独立 Harness 与真实客户端闭环 | Gateway/Runtime、薄 Fabric Bridge、正常账号图形客户端和 Server Profile 入测试服；验证 A/B 模式、IPC 鉴权、断线身份、基本移动/使用及 Dashboard 故障隔离 | 暂停基线栈，修正 Runtime/Bridge 边界或版本；不把心智塞回 Mod，也不降级成协议 Bot 却继续声称真客户端 |
| Dashboard 与观战隔离 | localhost 默认安全、实时状态序列、紧急停止、敏感字段、浏览器断线；Live View 测延迟/资源且不进入 PlayerMind | 未认证访问、浏览器可直发游戏输入或观战/真值污染认知均属阻断；关闭媒体不应停止 Kin |
| 合法身体与本地反射 | 取木/拾取/真实 GUI/箱炉/盾牌及局部建造分段测试，跌落中断；报告实际输入→服务器反馈、失败占比和 FPS/TPS/RTT | 精确缩小能力声明，标注未实现，修改动作原语；不能只看模型说已完成 |
| 社会人物与长期自主 | 两天以上包含无人指令生活、能放弃通关、错把误伤当攻击的纠正、陌生人/运行者/老友关系变化、死后身份连续 | 重做证据/情绪/目标更新，不套固定“攻击→报仇”故事或默认主人命令 |
| 知识与自主技能 | 版本新增/旧攻略、红石知识≠实战、查刷怪塔教程→候选→施工回报，旧技能在第二次任务复用并修订 | 原样保留候选与未知，不把检索到/写好流程当成功 |
| 公平/安全/合规 | 未见矿、墙后人、声音、矿透模式例外、聊天网页与重启记忆注入，明确服务器披露；记录拒绝及合法协作误拒 | 未授权数据路径、越权工具或输出泄漏属上线阻断；不得宣称零泄漏 |

每一行验收先写测试场景/预期观察/允许失败/实际样本数量/置信范围与环境，再定人类基线或体验阈值。平均数隐藏尾部延迟与稀有失败，需报 P95/P99、错误/成功条件和分组；测试中留下真实失败供复盘。设计没有数据时只定义计量项，不编造“正常人反应 180ms”“Kin 落地水 85%”等伪实测。对重大取舍按[设计决策](decisions.md)记录理由，商业/公开服上线不由研究完成自动授权。
