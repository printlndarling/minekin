# 开发前文档收口审计

审计时间：2026-09-17。本文回答“设计文档是否已经细化完成、还剩什么”的问题，并作为开发前唯一收口入口。输入审计对象为当时的 `README.md` 与 `docs/` 下 67 个 Markdown 文件；本轮新增本审计与重大确认清单后，仓库共有 70 个 Markdown 文件。

## 审计结论

当前文档已覆盖产品边界、单 Kin 玩家体验、PlayerMind、人格/情绪/关系/记忆、目标与学习、玩家等价感知、合法输入、真实客户端、独立 Harness、Dashboard、世界/服务器隔离、版本供应链、离线身份、持久化、安全、成本、回放和 P0 执行顺序。

本轮机械检查结果：

- 收口后 70 个 Markdown 文件；
- 456 个仓库内 Markdown 链接；
- 0 个失效内部链接；
- 0 个未被其他文档引用的 docs 文件；
- 40 个研究台账项；
- 0 个 `未查`、0 个 `查证中`、0 个当前静态研究阻断；
- 36 项需要真实客户端原型验证，1 项需要行为回放验证，2 项需要持续复核，1 项明确不纳入首版。

因此，**没有发现仍可仅靠继续写概念文档就解决的空白产品方向**。但这不等于项目已经得到运行证明：绝大多数底层能力必须由原型、受控服务器与回放数据验证。文档完整度和技术可运行性是两个不同门槛。

## 状态词的唯一语义

| 状态 | 含义 | 是否允许继续进入下一阶段 |
| --- | --- | --- |
| `DESIGN_CLOSED` | 产品边界、默认值、接口责任、失败回退和验收方法均已写明 | 可以实现对应最小原型；不能声称能力可用 |
| `EVIDENCE_BACKED_CANDIDATE` | 有官方文档、固定源码或论文支持一条有限实现路线 | 只允许按契约试验 |
| `PROTOTYPE_REQUIRED` | 成败依赖真实 Minecraft/Fabric/JVM/服务器/模型行为，静态资料无法证明 | 必须保留为开发阶段实验，不能用更多文字标成完成 |
| `FUTURE` | 已明确排除在单 Kin 原版首版之外 | 不阻断 P0 |
| `BLOCKED` | 没有安全可实施候选、许可不可接受或重大方向未确认 | 当前无此状态 |
| `TESTED` | 固定版本、环境、case 与 evidence bundle 已实际通过 | 当前没有任何底层能力达到此状态 |

文档中“候选”“必须实测”“需原型验证”是有意保留的诚实边界，不是漏写开放项。

## 已关闭的重大产品选择

以下方向不再开放讨论，除非用户主动改变目标：

1. 产品本体是独立 Runtime/Harness + Web Dashboard，自带受管理客户端后端；
2. 客户端内只保留版本化 Thin Fabric Bridge，不能把 Soul/Memory/Planner 塞回 Mod；
3. 真实 Minecraft Java 客户端身体，不回退为 Mineflayer/协议 Bot；
4. 默认本地离线身份，Microsoft/Xbox 认证只是显式可选适配器；
5. 单 Kin、原版生存、1.21.4 固定 bundle 优先；多 Kin、模组、多版本属于 future；
6. 外部 VLM 默认关闭，Live View 给人看，不持续消耗视觉 token；
7. 玩家等价结构化观察为默认，任何超界读取必须显式配置、标记来源并审计；
8. Kin 是自主玩家，不接受运行者主人/奴隶模型，重大游戏目标由 Kin 决定；
9. Persona、Memory、Goal 与通用技能跨会话持久；世界现实按 world context/epoch 隔离；
10. P0 先证明 Launcher→Bridge→Session→JOIN→Snapshot→Input→Recovery，再开发上层心智体验。

[重大待确认清单](critical-confirmations.md)当前为空。

## 仍需真实原型回答的 P0 阻断项

这些不是继续查资料能消除的文档欠债：

| Gate | 必须得到的实际证据 | 失败后的有限回退 |
| --- | --- | --- |
| E01 Bundle/Launcher | 全新 Linux 环境解析固定元数据、核摘要、Java 21 + 虚拟显示启动真客户端 | 收窄平台或修正 bundle；不接管宿主客户端 |
| E02 Offline Session | OFF-A/OFF-B 到真实 Session、offline-mode JOIN、服务端身份和日志脱敏 | 调整有界候选；无赢家则阻断 P0 |
| E03 Thin Bridge/IPC | 主菜单握手、client thread预算、generation、背压、断线松键 | 缩小 Bridge contract；不把心智搬入 JVM |
| E04 Player-equivalent snapshot | JOIN 后首快照、视锥/遮挡 canary、oracle 不回流 | 收紧字段或自写过滤；不直接开放客户端全量世界 |
| E05 Minimal control | look/move/release 经正常客户端动作，服务端可观察且故障时不粘键 | 修正输入适配；不使用传送/直接状态写入 |
| E06 Recovery/evidence | Runtime/Bridge/server 强杀、身份连续、三时间线和不可变 evidence bundle | 不晋级 `P0_CORE_TESTED` |
| E07 Injection/security | 聊天/网页/记忆/工具攻击回放不提升权限、不持久污染、不泄露敏感字段 | 缩小模型上下文和工具面；不能宣称零泄漏 |

执行顺序以[P0 核心原型执行计划](p0-prototype-execution-plan.md)为准。E01–E07 未实际通过前，项目不能宣布“底层已可用”。

## P0 之后仍需验证的能力

这些已经有设计和候选接口，但不应塞进第一个 core 原型：

- 受限地图导航、Baritone 隔离变体或自写局部导航；
- 砍树、掉落拾取、GUI 合成、炉/箱/床与资源依赖图；
- PvE/PvP、盾牌、瞄准、撤退与人类化技能成长；
- 逐块建造、蓝图校验、材料预算与红石知识/实操分离；
- 多维度发展、末影龙里程碑与通关后生活；
- PlayerMind、人格、情绪、社会归因、长期记忆和自主目标回放；
- 世界书、网页研究、SkillSpec 生成/晋级/降级；
- HOST_INTEGRATED_LAN、世界保存恢复和同 JVM 服务端真值隔离；
- Dashboard Live View、资源预算与长期运行。

每项已有对应契约和失败路线；它们属于分阶段工程验证，不阻断 W00 开始，但会阻断相关功能被宣传为已支持。

## 不再使用的模糊标签

为避免开放项看起来像无人处理：

- 旧版开放技术清单改称“已收敛候选与强制原型验证”；
- 旧版开放选择范围改为“默认执行决议与校准点”；
- 旧版未冻结参数改为“必须由原型冻结的参数”；
- 研究台账只用：未查、查证中、有证据的可行方案、需原型验证、阻断；
- future 不写成当前欠债，必须明确进入条件。

## 开发放行判断

目前可以放行的只有：按 W00 开始**最小 P0 验证性原型**。这不等于放行全面产品开发。

只有同时满足以下条件，才能宣布“可以进入上层实际开发阶段”：

1. W00–W70 的 mandatory cases 全部具有实际 evidence bundle；
2. P0 core 状态为 `TESTED`，而不是 candidate；
3. 没有 oracle/凭据泄漏、输入残留或无法分类的失败；
4. 许可证/SBOM 与固定 bundle 一致；
5. 失败回退没有改变真实客户端、玩家等价、独立 Harness 等核心方向；
6. [重大待确认清单](critical-confirmations.md)仍无未决项。

当前判定：**文档设计已达到可开始 P0 验证性原型的细度；运行证据尚为零，不能宣布全面开发就绪。**
