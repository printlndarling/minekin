# 架构与感知边界

## 模块与控制权

| 模块 | 职责 | 失败时的行为 |
| --- | --- | --- |
| Fabric 客户端适配器 | 获取自身状态、视听事件、合法输入与技能执行结果 | 停止新操作，保留安全退出能力 |
| 在线生命周期控制器 | 按模式与玩家在线事件决定加入、暂停、退出和重连 | 保存状态并停止新行为，避免重复登录 |
| 感知过滤器 | 将客户端数据转换为正常玩家可感知的观察 | 不把未经筛选的原始世界状态交给决策层 |
| 信念状态 | 维护最后观察时间、来源、置信度与过期规则 | 将失效信息标为未知，不当成实时真值 |
| 反射控制器 | 紧急生存动作、抢占行为层 | 模型不可用时仍能处理已实现的紧急动作 |
| 行为层 | 选择/执行任务，处理中断与恢复 | 回到保守的局部生存状态 |
| PlayerMind 与 LLM | 自主目标、社会判断、长期计划 | 不产生新高层目标；本地行为保持安全 |
| 外部工具网关 | 根据能力清单执行查资料等非实时任务；返回带来源与时间的结果 | 超时/不可用时告知角色，原有客户端控制不中断 |
| 技能适配器 | 导航、采集、使用物品等受约束的动作 | 反馈失败原因，不假报任务完成 |

高层计划只提交有版本号、有效期和前置条件的 `intent`。反射层随时抢占；中断时保存任务上下文，危险解除后重新检查前置条件再恢复。过期的 LLM 响应不得覆盖当前危险状态。任何低层动作都必须受当前真实客户端状态和服务器规则约束。

外部工具网关位于长程认知侧，与逐 tick 客户端回路隔离。它接受带目标、期限、能力要求的任务，在后台返回结构化结果、出处和失败原因；结果只是候选知识，不直接成为游戏真值或客户端动作。见[外部工具与自主查资料](external-tools.md)。

在线生命周期控制器只决定角色是否在世界中及是否恢复任务，不修改 PlayerMind 的价值判断。陪玩模式下真人离开时暂停待办、保存事件与意图并正常断开客户端；独立玩家模式可以在无人在线时继续运行。重连前检查账号会话、世界身份和旧任务前置条件，避免把过期的移动/攻击指令直接续上。具体体验与状态见[玩家在线模式](lifecycle.md)。

目标管理器归属每个 Kin 自己的 PlayerMind：长期方向拆成可达的中期项目和近期行动，并能在游戏日、里程碑、失败或新关系出现时调整。后续多 Kin 扩展为每个角色独立运行同一结构，每个客户端只获得自己的合法观察；角色间通过世界里可交流的渠道提出计划和共享约定，而非共享一份全知数据库。见[目标设计](goals.md)和[多 Kin 世界](multi-kin.md)。

## 时间尺度与预算

下表是设计目标，不是已有系统的性能保证。Minecraft 通常按 20 TPS 推进游戏逻辑，一个 tick 约 50 ms；具体实现需测量客户端帧率、服务器 TPS、网络时延和模组执行成本。

| 层级 | 目标节奏 | 例子 | 模型调用 |
| --- | --- | --- | --- |
| 本地反射 | 每客户端 tick 检查；触发后争取 1 tick 内开始动作 | 跌落、低血量、临近爆炸 | 无 |
| 局部控制 | 每 tick 或按技能反馈调整 | 寻路、战斗、避障 | 无 |
| 行为选择 | 约 0.5–5 秒，事件驱动可提前触发 | 继续采矿、暂停、撤退 | 可选 |
| 社会与长期规划 | 事件或分钟级 | 接受交易、改变关系、改建基地 | 按需 |

不能保证一次落地水必定成功：落点是否可见、水桶是否在快捷栏、服务器延迟、可操作的剩余 tick 和物理条件都会影响结果。优先把该场景做成有明确结果的实验，而不是承诺“毫秒级必救”。

### 悬崖跌落实验

1. 自身 `onGround` 变化、下降趋势和可见/可触碰的落点共同触发跌落预警；受击事件提高紧急等级。
2. 若可用物品与剩余时间允许，反射层抢占正在执行的计划，切快捷栏、转向可达落点并尝试正常使用水桶。
3. 如果没有合法可操作的落点，选择已有的替代技能或减伤措施；允许失败和死亡。
4. 记录触发 tick、输入 tick、视角调整、使用结果、服务器状态和失败原因。用重复试验衡量成功率与反应时延。

技能模型允许不同角色有不同反应延迟和操作误差，但误差不应掩盖隐蔽的数据越界。先证明动作链可用，再设定符合角色的表现范围。

## Human-Equivalent Perception Boundary

实现时必须区分“客户端持有数据”和“角色知道信息”。感知过滤器是每个决策入口唯一的数据来源；技能适配器也需限制寻路查询范围，避免从底层路径规划泄漏未见地形。

| 数据 | 可供决策的条件 | 禁止的捷径 |
| --- | --- | --- |
| 自身血量、饥饿、速度、HUD、背包 | 正常客户端呈现或操作可知 | 直接修改角色属性 |
| 实体与玩家 | 可见、有相应声音/受击线索，或曾经观察过 | 墙后精确坐标、视野外即时追踪 |
| 方块与地形 | 当前可见/接触或此前合理观察 | 按加载区块扫描地下矿物 |
| 箱子与他人物品 | 自己打开、看见转移或有人主动告知 | 偷看未打开箱子/他人背包 |
| 领地与建筑 | 基于亲历建造、约定、观察、公开告示 | 自动读取服务器插件的私有权属数据 |

声音提示可以让角色怀疑背后有生物，但不给出超出声源线索的精确坐标。已观察的信息随时间降低置信度。视觉截图用于识别建筑布局、复杂场景或行为语义；结构化状态用于快速、可核验的物理与自身状态判断。两者不得因为“用了截图”就忽略遮挡与知识来源。

## 数据与性能验证

在私人测试环境记录原始事件、过滤后观察、决策依据和合法输出；测试日志可以保留原始真值供离线评估，但线上 PlayerMind 不得访问它。建立可回放场景，比较角色信念与真实世界的差异，检查是否发生墙后追踪、未见矿物定位、未经观察的权属推断。

测量每层的触发至首次输入时延、tick 占用、技能成功率、错误抢占率、过期响应丢弃率、LLM 调用量和故障恢复时间。不要用固定毫秒数代替实测报告；报告应附 FPS/TPS、网络条件、物品配置与试验次数。
