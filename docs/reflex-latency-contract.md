# 紧急反射与行为夺权：验证方法

反射是 Kin 真客户端本地执行的**保命候选**，绝不让 LLM 截图→推理→回传介入下落/近距离爆炸/急救。20 TPS 对应正常逻辑周期约 50ms；[Minecraft 官方快照 23w43a](https://www.minecraft.net/en-us/article/minecraft-snapshot-23w43a)明确默认玩家模拟仍以 20 ticks/s 为基准，同时服务器可改变目标 tick 速率，这不是“任何危险都会 50ms 内发现、完成落地水”的保证。[Fabric 官方事件文档](https://docs.fabricmc.net/develop/events/)现在默认展示其他版本，证明事件回调机制的候选，不证明 1.21.4 目标 API 已打包/与 Baritone 稳定共存；运行前必须锁对应版本构件。

## 本地环与抢占契约

`filtered observation → hazard flag → reflex candidate selection → capability/skill check → arbitration → legal client input → next tick & server feedback`。本地观察只用自己可知的生命、下降/受击、快捷栏和**可见/可接触**落点；少量辅助碰撞预测属于明确标记的短时动作例外，不可写入地图或人物猜想。未装备水桶、落点不合法、剩余时间不足时可以改用已掌握回退/承伤，不装作人人都会 MLG。

仲裁次序：强制世界外停机/服务器禁止能力与输入合法性 > 紧急保命 > 已授权局部行为 > 高层意图。较低层当前破坏/攻击/GUI 点击须中断并返回原因，暂存 `intent_version`、前提和预计资源；危险消退后 Kin 或可验证行为层**重新检查**视野/物品/目标/关系再恢复。下落时不能让过期模型指令抢回转向/切槽；危险事件不自动指认或攻击撞人的玩家。反射失败、从墙后猜落点或技能不熟均可能致死；死后仍保留同一身份与真实经历。

| 测试条件 | 关键观测 | 不可编造的结论 |
| --- | --- | --- |
| 崖边受击且水桶在快捷栏，落点可见 | 受击/下落 tick、判定/抢占 tick、第一次转视角/切槽/使用 tick、客户端与服务端反馈，RTT/FPS/TPS | 重复样本成功率与误用率；不是 100% 成功保证 |
| 崖边受击但水桶不在快捷栏/无法使用 | 是否识别不可用并回退、死亡真实结果、有没有越过技能资格 | 知道方法不等于会操作 |
| 合成 GUI 或正在砍树突然爆炸/低血量 | 可取消当前 GUI/破坏、第一次保命输入、恢复时旧资源/目标是否失效 | 不能只看“模型说逃了” |
| 反射与模型回复同时到达，服务器延迟增大 | `intent_version` 防旧响应、排队积压、掉帧/P95/P99 响应和资源占用 | 逻辑 tick 的理论 50ms 非端到端实测 |
| 被玩家拍一下提醒 vs 重复致命攻击 | 先保命/注意到对方，再由高层根据关系/情境判断意图 | 受击不自动等于敌意/追杀 |

日志要用单调时钟和游戏 tick 同时记 `perception_ready`、`hazard_detected`、`arbitration_won`、`first_input`、`feedback`、`resolved/failed`；在私人测试环境分别报告 P50/P95/P99、个案失误与条件组合。原型中用同一物理场景对比空载/模型 5 秒超时/帧率低与多人服 RTT 高，若本地环占用使图形客户端明显掉帧，须缩短采样/过滤负载而非简单提高触发次数。与[感知实施](perception-implementation.md)和[成本回放](telemetry-cost-acceptance.md)协同核查。本文没有原型测量，开工前只能称“可试的本地方案”。
