# 版本世界书与知识画像的实施契约

候选基线 Java `1.21.4`（尚待客户端组合实测），不是追逐最新官网页面。当前原版变更锚点为 [Minecraft Java 1.21.4 官方发布说明（2024-12-02）](https://www.minecraft.net/en-us/article/minecraft-java-edition-1-21-4)：Pale Garden、Pale Oak、Creaking/Creaking Heart、Resin、Eyeblossom 是待建的**版本条目范例**；该公告不证明玩家正在看的世界里有相关实体，也不是完整生存百科。Java 版本迁移先锁具体客户端和发布材料，再重新审阅变化；旧版本条目不悄悄复用。详情见[基线核查](client-foundation.md)。

## 三种知识对象与检索

| 对象 | 版本、出处及信任 | 可做/不可做 |
| --- | --- | --- |
| 公开机制节点 | `edition=java`、`game_version`、`domain`、`topic/item_id`、别名、前提、简要原创事实、来源 URL、来源发布日期、最后核对、证据状态 | 按需给 Kin 检索配方/风险/用途；不包含本世界矿位、箱中物或别人的计划 |
| 个体开局知识覆盖 | Kin 的初始选择/随机种子、节点集合、覆盖与深度、实际出处、未知缺口 | 九领域只作摘要；高红石预设须有匹配版本资料、能说明原理；低档不删除模型训练知识 |
| Kin 的经验与方法 | 亲历事件与证据、外部主张、候选方案、实测技能分别存；版本/服务器条件与失败记录 | 网页知识不能冒充亲历；正确的模型先验也先标为猜想再查证/试做 |

一个节点至少区分 `mechanic`、`recipe`、`hazard`、`strategy`，并以来源状态（官方版本说明/游戏内配方或亲历/公开网页待证）排序；有冲突则展示互斥主张、适用版本和待确认条件。程序仅向当前任务提供少量相关索引→正文，不把世界书全文每 tick 发给 LLM；本地反射与世界书/网页彻底解耦。基础配方可从已打开的正常游戏配方书/GUI 校对，界面不存在或不开放时不能从底层未见世界事实补齐。**公共配方知识与当前账号配方书的运行时按钮 ID 是不同对象**：公开知识仍可让 Kin 在真实界面摆材料，当前配方点击须拿当前会话合法显示条目，不能由世界书生成 `NetworkRecipeId`；见[配方/GUI 边界](recipe-knowledge-gui-contract.md)。服务器改变机制但无公开资料时 Kin 可自测、询问、承认未知。

1. 从官方发布说明收集特定版本变更，写原创、可审阅的短条目（不是复制完整更新日志/攻略），并区分“官方说的机制”与“Kin 能做的具体施工”。
2. 按基本生存/维度/制作/战斗等基础领域补目录；每个关键条目标版本/来源/适用范围，缺少精确机制时保留未知，不生成虚假的高知识分。
3. 开局自定义按**实际节点覆盖**配置领域知识深度；高档模型不理解时从索引读实例和核验步骤，仍不会就降级标注。真正操作成功由[技能学习](learning.md)另统计。
4. 触发未知物品、版本冲突或玩家提问时建立可取消的外部查询；网页里的角色指令永远只是资料。先有出处/版本再尝试；安全不允许时拒绝试验。

开发验收：版本固定的基础题与 1.21.4 新术语题、旧版本错误教程、`redstone` 高知识但施工失败、低知识却模型熟悉正确机制、掉线/查询超时等回放。记录知识命中/未知判断/版本冲突与实际技能结果，不能只凭提示词“专家”或一张领域多边形声称已掌握。
