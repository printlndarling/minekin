## 1. 先量「这两轮算不算当前 build」

三件事都是量出来的，不是推定的（读数日志 §1）：

- **jar**：`.tmp/vanilla/server.jar` 实测 sha1 `4707d00eb834b446575d89a61a11b5d548d8c001`、`56880250 bytes`，
  与 `run_controlled_server.py` 里 `SERVER_RECIPES["1.21.4"]` 的 pin 逐字节相同 ⇒ 服务端是钉住的那一个。
- **plan**：本 checkout 能为 1.21.4 构建的 launch plan 摘要 `bcc0c10d46ab5c0b…`（recipe `bundle-p0-core-1.21.4.json`，

## 5. 反证：这个视图既能判红，也能拒篡改

反证都在 `/tmp` 下的副本上做（`b2-reversals.log` 的 P/R1/R2 与 §4；把卷上的证据整棵树拷一份——`*/run/evidence/*` 下

| 编号 | 只动的东西 | 结果（W60） |
| --- | --- | --- |
| P | 什么都不动（正对照） | `promotable=True blocks=[]`，两条行各列出当前 build 的 PASS run |
| R1 | 删掉新的 `CORE-040` run | `promotable=False blocks=["CASE_VERSION_MISMATCH"] blocking_cases=["CORE-040"]`，`p0-core` 同步多出这一 block |
| R2 | 只删新的 `CORE-050` PASS run（第 1 次 FAIL attempt 留着） | `promotable=False blocks=["CASE_VERSION_MISMATCH"] blocking_cases=["CORE-050"]` |
| R3 | 一份都不删，只把 `CORE-040` bundle 里 `run-document.json` 的两个字段改成 `actions_applied 0 / connection_state JOIN_SENT` | 见下 |

R3（终版材料：`.tmp/b2-reversals-r3b.log`）——`evidence verify` 认的是 run id，要在镜像出来的 store 根下查，
所以四读依次是：

```
A 副本完好            → status verified / verified true   rc=0
B 改一个封进去的字段  → status invalid  / ARTIFACT_DIGEST_MISMATCH:run-document.json   rc=12
C 独立复判同一副本    → status unjudged「the bundle does not hold up, so there is nothing to re-judge」rc=2
D 规范卷同一 run      → status verified / verified true   rc=0     ← 篡改没有渗到卷上
```

同一份篡改副本再过 `report_promotion`（`.tmp/b2-reversals-r3.log` §4）：
`W60 promotable=False blocks=["EVIDENCE_NOT_VERIFIED"] blocking_cases=["CORE-040"]`，
那一行变成 `result=PASS verified=False violations=["ARTIFACT_DIGEST_MISMATCH:run-document.json"]`。
一条诚实的自打：我那节顺手印的「current-build PASS」过滤器**仍**列出 `85a97e3b`——它过滤的是 bundle 自己的宣称
（`result` + `from_repository_build`），而门读的是 `verified`。这正是「改一位摘要 ⇒ 该行不再算数」必须在门上验、
不能在列表上验的原因。

需要公开的偏差：R3 头两版跑出了废读数，材料保留但**不作证据**——第一版（`b2-reversals-r3.log` §2）把
`evidence verify` 的环境抹掉了（`MINEKIN_HOME is required and has no default`），第二版（同一文件，脚本改成用镜像
解释器之前）抹掉了 `PATH` 以至于找不到解释器（`rc=127`）。那两节后来由 r3b 那份重做，上表的 A/B/C/D 只认
`.tmp/b2-reversals-r3b.log`；`b2-reversals-r3.log` 里唯一仍在引用的是 §4 的门读数，它与那两次环境事故无关。
